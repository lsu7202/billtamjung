### A. ~~법정 대비 건폐·용적을 한 산식으로~~ **끝냄(09-04)**

법정치를 다르게 내던 곳은 **검색 하나였다.** 처음 적을 때 보고서까지 셋이라 했는데,
보고서는 이미 필지 원장을 읽고 있었다 — 잘못 적었다.

| 어디 | 법정치를 어디서 | 방향 |
|---|---|---|
| 건물 상세(ParcelBlock) | 필지 원장(토지이음 산식·0153 배열) | 현재 − 법정 |
| 보고서·매력도 | 같은 원장을 직접 읽음(원래 그랬다) | 법정 − 현재(「증축 여지」) |
| 검색 필터 | ~~`use_zone` CASE 하드코딩~~ → `master.building_legal` | 법정 − 현재(0에서 끊음) |

`scripts/build_building_legal.py` 를 새로 만들어 건물마다 한 번 펴 뒀다.
산식은 건물 상세와 **글자 그대로 같다**(building_parcels → parcels, 병기 제외, 최대값).
표본 1,000동 대조 0건 불일치. 515,007행 · 커버리지 87.1%.

옛 CASE 는 「일반상업지역이면 800%」로 잘라 놓아 **18,289동이 상세와 다른 값**을 받았다.
걸침 필지를 못 다루는 것이 큰 원인이다(0153 에서 고친 그 문제).

**부호는 일부러 다르게 둔다.** 상세는 「법정 대비」(현재−법정, 넘으면 +·빨강),
검색은 「얼마나 더 지을 수 있나」(법정−현재, 0에서 끊음). 묻는 것이 다르다.
같아야 하는 것은 법정치이고, 그건 이제 한 곳에서 온다.

**남은 것:** `pnu` 는 있는데 `building_parcels` 에 줄이 없는 건물 **57,228동**.
상세도 검색도 법정치를 못 낸다. 건물의 pnu 로 직접 붙이면 메워지지만 그건 우회다 —
원장 연결에서 고쳐야 한다(C 에서 같이).

화면은 데이터가 성해진 뒤에 그린다. **거리 열은 안 쓴다**(구역 안·m·동 단위가 한 칸에 안 들어간다).
위치를 아는 것은 지도에 아이콘으로, 목록은 날짜순으로.
