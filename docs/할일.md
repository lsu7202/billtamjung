### A. ~~법정 대비 건폐·용적을 한 산식으로~~ **끝냄(09-04)**

법정치를 다르게 내던 곳은 **검색 하나였다.** 처음 적을 때 보고서까지 셋이라 했는데,
보고서는 이미 필지 원장을 읽고 있었다 — 잘못 적었다.

| 어디 | 법정치를 어디서 | 방향 |
|---|---|---|
| 건물 상세(ParcelBlock) | 필지 원장(토지이음 산식·0153 배열) | 현재 − 법정 |
| 보고서·매력도 | 같은 원장을 직접 읽음(원래 그랬다) | 법정 − 현재(「증축 여지」) |
| 검색 필터 | ~~`use_zone` CASE 하드코딩~~ → `master.building_legal` | 법정 − 현재(0에서 끊음) |

`scripts/build_building_legal.py` 를 새로 만들어 건물마다 한 번 펴 뒀다.
산식은 건물 상세와 **글자 그대로 같다**(building_parcels → parcels, 병기 제외, 최대값).
표본 1,000동 대조 0건 불일치. 515,007행 · 커버리지 87.1%.

옛 CASE 는 「일반상업지역이면 800%」로 잘라 놓아 **18,289동이 상세와 다른 값**을 받았다.
걸침 필지를 못 다루는 것이 큰 원인이다(0153 에서 고친 그 문제).

**부호는 일부러 다르게 둔다.** 상세는 「법정 대비」(현재−법정, 넘으면 +·빨강),
검색은 「얼마나 더 지을 수 있나」(법정−현재, 0에서 끊음). 묻는 것이 다르다.
같아야 하는 것은 법정치이고, 그건 이제 한 곳에서 온다.

**남은 것:** `pnu` 는 있는데 `building_parcels` 에 줄이 없는 건물 **57,228동**.
상세도 검색도 법정치를 못 낸다. 건물의 pnu 로 직접 붙이면 메워지지만 그건 우회다 —
원장 연결에서 고쳐야 한다(C 에서 같이).

## 2026-09-04 에 끝낸 것

1. **건물정보 승강기는 대장 기준** — 코드 완료, 값은 C 에서 갈린다.
   빌더 `_elev`(대장 전용)·`_elev_ext`(공단) 분리 · 0156 `elevator_ext` · API `_ref` · 화면 참조 곁말.
   건폐율·용적률도 대장이 비면 계산값을 옆에 참조로.
2. **평·㎡ 토글에 공시지가가 따라온다.** GongsiCard·GongsiTable 이 unit 을 받는다. 기본 평.
3. **층별 임대정보**
   - 용도 제거, **상호명** 신설(0155 `tenant_name`)
   - 순서 1층 → 위 → 옥탑 → 지하 (FloorRows `frank` · floor_rents ORDER BY · RentPanel `floorRank`)
   - 「＋ 호실」이 한 호실짜리 층에 안 뜨던 것 고침
   - **호실 번호를 지어내지 않는다.** 대장은 호실을 안 주므로 대장 줄에는 호실이 없고,
     한 호실뿐인 층도 호실을 안 보여준다. 팀이 ＋호실로 나눌 때만 101·102 로 선다.
   - **`sfloor` 버그**: 「옥탑1층」이 「1층」과 같은 층으로 읽혀 1층이 「102호」로 떴다. 옥탑을 따로 센다.
   - 여러 호실 층의 접기 제거. 항상 펴져 있다.
   - 입력 카드: 상호명·면적·상태 한 줄, 호실은 그 아래.
4. **「10년 전 대비 +5%」**
5. **「법정 대비 건폐 · 용적」** = 현재 − 법정. 넘으면 + 이고 빨강. **소수점 1자리.** `%p` 전부 제거.
6. **주변시세 막대 호버** — 막대 전체에 「이 건물 … · 주변 시세 …」, 눈금은 잡는 영역을 넓혔다.
7. **지도 검색 엔터 이동** — 자동완성이 180ms 늦어 헛돌던 것. 친 글자로 그 자리에서 묻는다.
8. **「도산대로 · 오피스 요율로 역산」 스판 삭제**
9. **안내 스판 전부 삭제** — 「매매가를 넣으면 섭니다」 외 여섯.
