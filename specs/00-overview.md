# 빌탐정 — 프로젝트 개요

> 본 문서는 빌탐정 프로젝트의 **단일 출처(Source of Truth)** 개요 문서입니다.
> 화면 명세는 `02-screens/`, 데이터 정의는 `04-data/`를 참조하세요.

---

## 1. 프로젝트 개요

- **서비스명**: 빌탐정 — *신뢰할 수 있는 부동산 가치 분석 파트너*
- **한 줄 정의**: 서울 내 건물의 건축물·토지 데이터부터 매물 관리, 가치 분석까지를 하나의 워크플로우로 통합한 건물 중개인용 생태계.
- **타깃 사용자**: 건물(빌딩) 중개인 — 매물 발굴 및 고객 관리 업무 담당자.

### 1.1 배경 및 문제 정의
건물 중개 시장에서 중개인의 **매물 찾기 및 고객 관리 업무는 복잡성이 매우 높다.** 기존 서비스들은 다음 문제를 가진다.

1. **데이터 분산** — 서울 내 건물의 가치를 판단하는 주요 근거(건축물 데이터, 토지 데이터 등)가 한곳에 모여 있지 않다.
2. **워크플로우 단절** — 데이터가 일부 존재하더라도, 중개 업무의 핵심 워크플로우인 **매물 관리 시스템으로 이어지지 않는다.**
3. **통합 생태계 부재** — 중개인의 업무를 하나의 흐름으로 잇는 통합 생태계가 없다. (= 가장 큰 문제)
4. **얕은 분석 / 신뢰성 부족** — 기존 가치 분석 서비스는 세부 기준을 무시하고 지나치게 기본적인 기준만 제시하여 신뢰성이 떨어진다.

### 1.2 해결 방향
빌탐정은 **데이터 통합 + 매물 관리 워크플로우 연결 + 심화 가치 분석**을 하나로 묶어 위 문제를 통합적으로 해결한다.

## 2. 요구사항

> 본 단계의 요구사항은 **요약 수준**이며, 세부 사항은 이후 화면 명세(`02-screens/`)와 데이터 정의(`04-data/`)에서 구체화한다.

### 2.1 매물 통합검색 및 필터 *(검색)*
**대목**: 서울 내 모든 매물을 통합 조회한다.

- 서울 내 **모든 주소**에 대해 데이터 검색이 가능하다.
- **필터**를 통해 조건별 검색이 가능하다.
- 검색 결과는 **3종으로 분류**되어 우선순위를 한눈에 파악할 수 있다.
  - **광고 매물**: 광고가가 존재하는 매물. → 매도자가 매물을 내놓은 상태 → 매매로 이어질 확률이 높음.
  - **내 매물**: "매물 등록" 절차를 통해 담당자가 지정된 매물. → 과거 매도자 연락처 확보 등 이점이 있음.
  - **일반 매물**: 위 두 분류에 속하지 않는 매물.

### 2.2 매물 세부 내역 및 내 매물 관리
**대목**: 조회한 매물의 세부 내역을 확인하고 내 매물로 관리한다.

- **위키**: 매물에 대한 특이사항을 **집단지성으로 관리하는 커뮤니티** 기능.
- **수정이력**: 이용자들의 매물 세부 내역 수정 이력. *(특정 한 데이터에 대해서만 수정 가능)*
- **데이터 정보**: 금액정보, 상세정보, 건물정보, 토지정보 등 매물의 전체 데이터 표시.

### 2.3 가치분석보고서
**대목**: 매물의 가치를 분석한 산출물을 문서로 제공한다.

- **브리핑 자료 (PPT)**: 특정 매물의 기본적인 건물정보·위치정보 등으로 구성된 **기초자료**.
- **빌탐정 매물분석보고서 (PPT)**: 특정 매물의 가치를 분석한 **심화 보고서**.

## 3. 용어집 (Glossary)

> 도메인 용어 + 앱 용어. 요구사항 구체화 과정에서 계속 추가한다.

### 3.1 앱 용어
| 용어 | 정의 | 비고 |
|---|---|---|
| 광고 매물 | 광고가가 존재하는 매물 | 매매 가능성 높음 |
| 내 매물 | "매물 등록"으로 담당자가 지정된 매물 | 연락처 등 확보 |
| 일반 매물 | 광고·내 매물에 속하지 않는 일반 조회 매물 | |
| 위키 | 매물 특이사항을 집단지성으로 관리하는 커뮤니티 | |
| 수정이력 | 매물 세부 데이터의 수정 기록 (단일 데이터 단위) | |
| 브리핑 자료 | 기본 정보 기반 기초 PPT | 산출물 |
| 매물분석보고서 | 가치 심화 분석 PPT | 산출물 |

### 3.2 도메인 용어 *(피그마/요구사항에서 도출, 정의 보강 필요)*

> **단위 표기 규칙**: 면적은 ㎡를 원천 저장 단위로 하고, 화면에서 평(3.3058㎡) 병기. 금액은 원(KRW) 저장, 화면은 억/만원 단위 포맷. 비율은 % 또는 %p(차이값).

| 용어 | 정의 | 단위 | 출처 |
|---|---|---|---|
| 연면적 | 건물 각 층 바닥면적의 합 | ㎡ (평 병기) | 건축물대장 |
| 대지면적 | 건물이 위치한 필지의 수평투영면적 | ㎡ (평 병기) | 건축물대장/토지대장 |
| 건축면적 | 건축물 외벽 중심선 기준 수평투영면적 | ㎡ (평 병기) | 건축물대장 |
| 건폐율 | 대지면적 대비 건축면적 비율 | % | 계산/대장 |
| 용적률 | 대지면적 대비 연면적(용적률 산정용) 비율 | % | 계산/대장 |
| 건폐율 여유분 | 법정 건폐율 − 현재 건폐율 | %p | 계산(파생) |
| 용적률 여유분 | 법정 용적률 − 현재 용적률 | %p | 계산(파생) |
| 공시지가 | 국가가 산정·공시하는 토지 단위면적당 가격 | 원/㎡ | 부동산공시가격 |
| 매매가 | 건물의 매매 가격 | 원 (억 표기) | 매물/광고 |
| 보증금 | 임대차 보증금 | 원 | 매물 |
| 임대료 | 월 임대료 | 원/월 | 매물 |
| 관리비 | 월 관리비 | 원/월 | 매물 |
| 명도 | 점유자를 내보내고 부동산을 비우는 것 | (상태값) | 등기/현황 |
| 멸실 | 건물이 철거·소멸되어 등기상 사라진 상태 | (상태값) | 등기 |
| 평단가 | 평(3.3058㎡)당 가격 | 원/평 | 계산(파생) |
| 수익률 | 매매가 대비 순임대수익 비율 | % | 계산(파생) |
| 자기자본수익률 | 자기자본 대비 순수익 비율 | % | 계산(파생) |
| 공시지가 상승률 | 직전연도 대비 공시지가 증가율 | % | 계산(파생) |

## 4. 문서 규칙 (Conventions)

### 4.1 ID 체계
- **화면 ID**: `S00` (예: `S01-매물목록`, `S02-매물상세`)
- **필드 ID**: `snake_case` 영문 (예: `sale_price`, `far_ratio`)
- **계산식 ID**: `F-00` (예: `F-05 수익률`)
- **출처 ID**: `SRC-00` (예: `SRC-01 건축물대장`)
- **요구사항 ID**: `R-0.0` (예: `R-2.1 매물 통합검색`)

### 4.2 데이터 표기 규칙
- 모든 필드는 `04-data/data-dictionary.md`에 **1필드 = 1행**으로 등록한다.
- 파생값은 반드시 **계산식 ID**를 가지며 `04-data/formulas.md`에 식을 정의한다.
- 모든 원천 데이터는 **출처(SRC)** 와 **수집방식**(파일/크롤링/수기 — **API 없음**)을 명시한다. → `04-data/data-overview.md`
- 데이터의 **신뢰도**(공식/추정)를 구분 표기한다. (예: 매매가=추정, 공시지가=공식)

### 4.3 문서 작성 규칙
- 화면 1개 = 파일 1개 (`02-screens/`).
- 시각 원본은 Figma, **정의의 단일 출처는 본 specs 문서**.
- 변경은 Git으로 추적한다.
