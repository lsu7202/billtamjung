# S04c 상태 — 사람이 고른다

> 2026-09-29 대표 결정 · 마이그레이션 0199. [S04b](S04b-업무-사다리와-필드.md)의 자동 판정 사다리를 대신한다.

## 1. 원칙

- 상태는 **사무소가 만들고, 매물 · 고객마다 손으로 고른다**(부기사 방식). 입력한 칸으로 단계를 계산하지 않는다.
- 판정 재료였던 칸(통화 · 의사 · 급함 · 매도 시기 · 명도 · 용도변경 · 멸실 · 임대 확인)은 **정보 칸으로 남는다**. 상태를 바꾸지 않는다.
- 매수자 채택(`picked_at`) · 안 산다(`dropped_at`)는 사람이 누르는 것만 남는다. 계약 일정 완료 · 계약 기록이 채택을 켜지 않는다.
- 모르면 미지정(null). 기본 상태를 지어 채우지 않는다.

## 2. 스키마

| 표 · 칸 | 내용 |
|---|---|
| `app.statuses` (새 표) | `id` · `team_id`(팀 삭제 시 함께) · `kind`(`listing` · `buyer`) · `name`(1~12자, 팀 · 종류 안에서 유일) · `color`(`#RRGGBB`) · `sort` · `created_at` |
| `app.listings` + | `status_id`(→ statuses, 상태를 지우면 null) · `sold_on` date · `sold_price` bigint(원) |
| `app.buyers` + | `status_id`(→ statuses) |
| `app.seed_statuses(team_id)` | 기본 상태를 넣는 함수. 팀이 생기면 트리거 `team_statuses`가 부른다 |
| 지운 것 | 뷰 `v_listing_stage` · `v_buyer_stage` · `v_proposal_stage`, 함수 `nego_rank()`, 표 `stops` · `_proposals_bak_0141` · `_proposal_events_bak_0141` |

**기본 상태**

| 종류 | 이름(순서) | 색 |
|---|---|---|
| 매물 | 작업 · 준비 · 보류 · 완료 | 파랑 · 회색 · 빨강 · 검정 |
| 고객 | 진행 · 계약 · 보류 · 종료 · 해약 | 파랑 · 검정 · 빨강 · 회색 · 연회색 |

- **완료**(매물)를 고를 때만 매각일 · 매각금액을 같이 받는다. 완료가 아닌 상태로 바꾸면 둘은 비운다.
- 이름으로 뜻을 읽는 곳은 셋이다. 이름을 바꾸면 이 동작이 따라오지 않는다.
  - 매물 「완료」: 광고 탭의 계약됨 표시, 매수자 담기 창에서 빼기
  - 매물 · 고객 「보류」: 연락할 차례(`/sales/today`)에서 빼기

## 3. API

모두 중개사 전용(`current_user`). 팀 밖의 상태 id는 422.

| 메서드 · 경로 | 몸통 · 쿼리 | 하는 일 |
|---|---|---|
| `GET /statuses?kind=listing\|buyer` | | 팀의 상태 목록(순서대로) + 상태마다 쓰는 건수 `n` |
| `POST /statuses` | `{kind, name, color}` | 더하기. 맨 뒤에 선다. 같은 이름이면 409 |
| `PATCH /statuses/{id}` | `{name?, color?}` | 이름 · 색 고치기 |
| `PUT /statuses/order` | `{kind, ids[]}` | 순서 다시 매기기 |
| `DELETE /statuses/{id}?move_to=` | | 지우기. 그 상태의 매물 · 고객을 `move_to`로 옮긴다(없으면 미지정) |
| `PUT /listings/{pk}/status` | `{status_id \| null, sold_on?, sold_price?}` | 매물 상태 고르기 |
| `PUT /buyers/{id}/status` | `{status_id \| null}` | 고객 상태 고르기 |

**응답에 실리는 칸**
- `GET /sales/sellers`: `status_id` · `status_name` · `status_color` · `sold_on` · `sold_price`. 사다리 칸(`stage` · `passed` · `s1~s6` · `cells` · `nego` · `stop_*` · `cell_last_on`)은 뺐다.
- `GET /buyers`: `status_name` · `status_color`(`status_id`는 행 그대로). `activity` · `dealt` · `nego` · `b_stage` · `stop_*`는 뺐다.
- `GET /proposals`: 사다리 칸(`d_stage` · `d2~d8` · `deal_cells` · `nego` · `buyer_dealt` · `listing_dealt` · `stop_*`)을 빼고 `picked_at` · `dropped_at`만 남는다.
- 지운 API: `/stops` 전부, `GET /buildings/{pk}/reject-summary`.

## 4. 화면

- **매물관리 표**: 「상태」 필터 = 사무소 상태 + 미지정(건수). 상태 열을 누르면 칩이 떠 바로 바꾼다. 「여부」의 보류는 뺐다.
- **매물 · 고객 모달**: 머리의 상태 배지를 누르면 칩. 보류 탭과 요약의 합의 문장(「합의중 · 계약예정」)은 없앴다. 짝 줄은 채택 · 안 산다만 보인다.
- **고객 목록**: 위 칩 줄 = 고객 상태 + 미지정.
- **마이페이지 → 사무소**: 「매물 상태」 · 「고객 상태」 판. 색 점 = 팔레트, 이름 = 클릭-편집, ↑ = 순서, 휴지통 = 옮길 곳을 고른 뒤 지우기, ＋ 상태 추가.
