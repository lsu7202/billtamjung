## 1. 목적/역할
- 로그인한 **개인 계정**의 허브: 프로필 · 크레딧 잔액/내역 · 구독 플랜 · 저장한 검색조건 · **팀(공유 그룹)** · 결제 · 계정설정.
- 계정 = **사적 레이어 소유자**(내 매물·CRM·크레딧). 팀은 그 위에 얹는 **공유 레이어**.

## 2. 진입 · 이탈
- **진입**: 상단 GNB 프로필/⚙︙ → 마이페이지. (로그인 필수 — 미인증이면 [[S00-로그인]])
- **이탈**: 각 섹션 액션은 인플레이스(모달) 처리 후 잔류. 로그아웃 → S00.

### 3.5 팀 · 직원 계정 [정식]  ★핵심 구조
- **모델**: [[S00-로그인]]의 **"1 전화번호 = 1 계정"을 팀에서도 유지.** 팀원은 **각자 개인 계정·개인 구독**(전화번호 인증). 팀은 그 개인 계정들을 묶어 **데이터를 공유하는 그룹** — 팀 자체는 결제 주체가 아님.

- **★ 팀 생성 시점 = 계정 생성 시 자동** *(확정 2026-07-19)*
  - [규칙] **가입하면 그 즉시 본인이 대표인 1인 팀이 자동 생성된다.** 별도의 "팀 만들기" 화면·버튼은 **없다.**
  - [규칙] 기본 팀명 = 가입 시 입력한 **중개사무소명**, 비웠으면 `{이름} 팀`. 대표가 나중에 변경 가능.
  - [규칙] MVP 유저는 이 1인 팀 상태로 쓴다. **정식에서 팀원을 초대하면 같은 팀에 합류**하는 것이며, 팀이 새로 생기지 않는다.
  - **왜 이렇게 하는가**
    1. **마이그레이션 비용 0** — `team_id`가 처음부터 모든 사적 레이어의 **NOT NULL 키**가 된다. 나중에 팀 기능을 켤 때 백필이 필요 없다. (`05-business/mvp-scope.md` "소유권 컬럼은 미리 심어둔다" 지시의 실행형)
    2. **담당자 드롭다운 소스 문제 해결** — 담당자는 "내 팀 멤버 목록"인데([[S02-매물상세]] §4.1), MVP 솔로도 1인 팀이므로 **본인 1명이 뜬다.** 예외 분기 불필요.
    3. **미정의 플로우 하나가 사라짐** — 팀 생성 화면을 설계·구현할 필요가 없다.
  - [예외] 대표는 자기 팀을 떠날 수 없다(팀에 항상 대표 1명 존재). 대표 위임·팀 삭제는 [정식] TBD.
  - → "팀원은 각자 번호가 다른데 1번호=1계정과 상충?" 이라는 우려 해소: 팀원은 별도 계정이 **아니라** 각자 자기 계정으로 **합류**만 함. 계정을 대신 만들어 주지 않음.
- **역할**
  | 역할 | 권한 |
  |---|---|
  | 대표(관리자) | 팀 생성·초대·제외·공유범위 설정. 팀당 1명(위임 [정식]). |
  | 팀원 | 초대 수락 시 합류. 공유범위 내에서 팀 매물·CRM·위키 조회. 자기 구독·크레딧은 개인 소유. |
- **초대 플로우** [규칙]
  1. 대표 `＋ 팀원 초대` → **전화번호 또는 이메일** 입력.
  2. 초대 발송 → 상대가 **이미 가입 계정**이면 알림/문자로 수락 링크 · **미가입**이면 가입 유도(가입 후 자동 합류).
  3. 상대가 수락 → 그의 **개인 계정이 팀에 연결**(계정 신규 생성 아님).
  4. 목록에 `활성`/`초대 대기` 상태 표시. 대기 건은 `재전송`·`취소`.
- **공유 범위** [규칙] *(재정의 2026-07-19 — 모드 선택 폐기, 아래로 고정)*
  | 대상 | 정책 |
  |---|---|
  | 매물 데이터·오버레이·업무 탭·메모·위키 | **팀 전체 공유**(양방향 고정). 각자 다른 값이 보이면 협업이 안 되므로 모드 선택을 두지 않는다. 소유자명·관계·협조도·긴급도·진행상태·담당자 모두 팀원이 본다. |
  | **① 전화번호** · **② 비밀메모** | **담당자 본인 + 대표(관리자)만.** → 팀 전체 공유의 **유일한 예외 2곳**. 경쟁사(부기사)도 이 두 곳에만 제한을 건다. |
  | 즐겨찾기 | **개인 전용**(팀 공유 X) — 개인 북마크이므로. |
  | 크레딧·구독 | **개인 귀속**(공유 안 됨). |
  - ~~기본(단방향)/전부 공유(양방향) 모드 선택~~ **폐기** — 열람 제한은 위 2곳(전화번호·비밀메모)만 남긴다. 나머지는 전부 공유.
  - [데이터] 향후 세분 권한을 얹을 수 있도록 **소유권 컬럼(누구/어느 팀 데이터인지)은 유지**한다(`05-business/mvp-scope.md` 데이터 모델 유의).

- **★ 매물 선점 (담당자 지정)** [규칙] *(신설 2026-07-19)*
  - **팀 내 1매물 = 1담당자.** 팀원 중 누군가 매물을 등록(담당자 지정)하면 **다른 팀원도, 대표도 그 매물을 자기 내 매물로 등록할 수 없다.**
  - **대표가 예외를 받을 필요가 없는 이유**: 대표는 어차피 팀 전원의 매물을 열람할 수 있으므로, 본인이 별도로 선점할 실익이 없다. → **열람 권한과 선점 권한을 분리**해 권한 매트릭스 없이 해결.
  - **팀 간에는 무관.** 다른 팀이 같은 건물을 선점하고 있어도 우리 팀 선점에 영향 없다(팀별 독립).
  - [규칙] **판정은 담당자 지정 여부만.** 진행상태(준비중~매각/철회)와 무관하다 — 진행상태는 **딜의 사실**이지 담당자 소속을 정하는 값이 아니다(`04-data/enums.md:16` "독립 축").
  - [규칙] **해제 = 명시적 행위.** 담당자를 비우면 선점이 풀려 다른 팀원이 잡을 수 있다. 상태 변경의 부수효과로 풀리지 않는다.
  - [규칙] **대표는 담당자를 재배정할 수 있다.** 퇴사·업무 이관 시 필요. 재배정해도 **진행상태는 그대로 유지**한다(사람이 바뀌었다고 딜의 사실을 고치지 않는다).
  - [예외] **담당자 퇴사·팀 제외** → 그 매물의 담당자는 **대표(관리자)에게 자동 귀속**된다. 담당자 없는 고아 상태를 만들지 않는다.
    - 이유: 방치되면 아무도 관리하지 않는 매물이 쌓인다. 대표에게 귀속하면 항상 책임자가 있고, 대표가 필요할 때 다른 팀원에게 재배정하면 된다.
    - 비밀메모·전화번호도 함께 승계된다(대표는 원래 열람 권한이 있으므로 접근 단절이 없다).
    - 진행상태는 그대로 유지한다.
  - [규칙] 활성/종료 매물 구분은 **별도 UI를 두지 않는다** — [[S01b-상세검색필터]] 대표조건 `진행상태` 필터로 처리(중복 UI 금지).
- **제외/탈퇴** [규칙] 대표가 팀원 `제외`, 또는 팀원 스스로 탈퇴 → 공유 접근 즉시 회수. 각자 개인 계정·데이터는 유지.
- [예외] 초대한 번호가 대표 본인 번호 → 차단. 이미 다른 팀 소속 팀원 초대 시 정책 = [정식] TBD(복수 팀 허용 여부).

- [데이터] 팀: 팀ID·대표(계정)·팀원목록(계정ID·상태·합류시각)·공유범위·초대(대상 번호/이메일·상태·발송시각).
- [데이터] 크레딧 원장: 계정별 트랜잭션(일시·항목·매물·변동·잔액·유형[소비/적립/지급]).
- [데이터] 저장검색: 계정별 조건 스냅샷(이름·필터JSON).

## 6. 예외
- 크레딧 0 + 보고서 시도 → 충전/업그레이드 유도([정식], 베타=기록만).
- 초대 대상 미응답 → 대기 유지, 재전송/취소.
- 소셜 연동 해제 시 최소 1개 로그인 수단 보장(전부 해제 차단).
