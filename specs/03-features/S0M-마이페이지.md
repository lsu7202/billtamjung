## 1. 목적/역할
- 로그인한 **개인 계정**의 허브: 프로필 · 크레딧 잔액/내역 · 구독 플랜 · 저장한 검색조건 · **팀(공유 그룹)** · 결제 · 계정설정.
- 계정 = **사적 레이어 소유자**(내 매물·CRM·크레딧). 팀은 그 위에 얹는 **공유 레이어**.

## 2. 진입 · 이탈
- **진입**: 상단 GNB 프로필/⚙︙ → 마이페이지. (로그인 필수 — 미인증이면 [[S00-로그인]])
- **이탈**: 각 섹션 액션은 인플레이스(모달) 처리 후 잔류. 로그아웃 → S00.

## 3. 화면 요소별 동작

| 프로필 수정 | [규칙] 이름·사무소명·비밀번호 수정 모달. 이메일·전화번호는 식별자 → 변경은 [정식]·재인증. |

### 3.2 크레딧 [MVP]
| 요소 | 동작 |
|---|---|
| 사용 가능 잔액 | [데이터] `월지급분 + 이월분`. 검색은 무제한, **보고서에만 크레딧 소모**. |
| 이번 달 사용 | [데이터] 당월 소모량(분석·브리핑 구분). |
| 이번 달 지급(월말 소멸) | [데이터] 플랜 월지급분 중 미사용 잔여(월말 소멸 대상). |
| 사용 내역 | [데이터] 일시·항목·매물·변동(±)·잔액 로그. 위키 기여 채택 등 **적립(+)**도 표시. |
| 크레딧 충전 | [정식] 추가 크레딧 구매 모달. 베타=무료(그림자 계량). |
- [규칙] **베타 기간**: 무결제·그림자 계량 — 크레딧은 소비만 기록, 실제 차단/결제 없음. 정식 전환 시 활성.

### 3.3 구독 플랜 [정식(결제)]
| 요소 | 동작 |

| 이용 중 / 업·다운그레이드 | [규칙] 플랜 변경 → 다음 결제주기 반영. |

### 3.5 팀 · 직원 계정 [정식]  ★핵심 구조
- **모델**: [[S00-로그인]]의 **"1 전화번호 = 1 계정"을 팀에서도 유지.** 팀원은 **각자 개인 계정·개인 구독**(전화번호 인증). 팀은 그 개인 계정들을 묶어 **데이터를 공유하는 그룹** — 팀 자체는 결제 주체가 아님.
  - → "팀원은 각자 번호가 다른데 1번호=1계정과 상충?" 이라는 우려 해소: 팀원은 별도 계정이 **아니라** 각자 자기 계정으로 **합류**만 함. 계정을 대신 만들어 주지 않음.
- **역할**
  | 역할 | 권한 |
  |---|---|
  | 대표(관리자) | 팀 생성·초대·제외·공유범위 설정. 팀당 1명(위임 [정식]). |
  | 팀원 | 초대 수락 시 합류. 공유범위 내에서 팀 매물·CRM·위키 조회. 자기 구독·크레딧은 개인 소유. |
- **초대 플로우** [규칙]
  1. 대표 `＋ 팀원 초대` → **전화번호 또는 이메일** 입력.
  2. 초대 발송 → 상대가 **이미 가입 계정**이면 알림/문자로 수락 링크 · **미가입**이면 가입 유도(가입 후 자동 합류).
  3. 상대가 수락 → 그의 **개인 계정이 팀에 연결**(계정 신규 생성 아님).
  4. 목록에 `활성`/`초대 대기` 상태 표시. 대기 건은 `재전송`·`취소`.
- **공유 범위** [규칙]
  | 모드 | 의미 |
  |---|---|
  | 기본(단방향) | 대표 → 팀원 매물 조회 가능 / 팀원 → 대표 조회 불가. |
  | 전부 공유(양방향) | 대표 ↔ 팀원 전체 양방향 공유. |
  - 공유 대상 = 매물풀·CRM·위키(사적 레이어). **크레딧·구독은 공유 안 됨**(개인 귀속).
- **제외/탈퇴** [규칙] 대표가 팀원 `제외`, 또는 팀원 스스로 탈퇴 → 공유 접근 즉시 회수. 각자 개인 계정·데이터는 유지.
- [예외] 초대한 번호가 대표 본인 번호 → 차단. 이미 다른 팀 소속 팀원 초대 시 정책 = [정식] TBD(복수 팀 허용 여부).

### 3.6 결제 수단 · 청구 [정식]
| 요소 | 동작 |
|---|---|
| 결제 수단 | [규칙] 카드 등록/변경. 베타=미등록 허용. |
| 다음 결제일·청구 이메일·청구 내역 | [데이터] 개인 구독 청구 정보. 베타=무료. |

### 3.7 계정 설정
| 요소 | 동작 |
|---|---|
| 비밀번호 변경 | [규칙] 현재→새 비번. |
| 알림 설정 | [정식] 채널·항목별 on/off. |
| 연결된 소셜 계정 | [정식] 카카오·네이버 연동 관리(전화번호 기준 자동연동 — [[S00-로그인]] §3.4). |
| 계정 삭제 | [정식] 삭제 시 사적 레이어·팀 소속 처리. **전화번호 체험판 이력은 어뷰징 방어용으로 유지**(재가입 정책 TBD). |

## 4. 상태 · 규칙
- [규칙] 크레딧·구독·팀 상태는 **개인 계정에 귀속**. 팀 합류/탈퇴가 개인 크레딧·구독에 영향 없음.
- [규칙] 대표가 구독 해지해도 팀은 유지(팀은 결제 주체 아님) — 단 공유 데이터 소유권/보존 정책 [정식] TBD.

## 5. 데이터 연결
- [데이터] 계정: [[S00-로그인]] §5 참조(이메일·전화번호·티어·크레딧잔량 등).
- [데이터] 팀: 팀ID·대표(계정)·팀원목록(계정ID·상태·합류시각)·공유범위·초대(대상 번호/이메일·상태·발송시각).
- [데이터] 크레딧 원장: 계정별 트랜잭션(일시·항목·매물·변동·잔액·유형[소비/적립/지급]).
- [데이터] 저장검색: 계정별 조건 스냅샷(이름·필터JSON).

## 6. 예외
- 크레딧 0 + 보고서 시도 → 충전/업그레이드 유도([정식], 베타=기록만).
- 초대 대상 미응답 → 대기 유지, 재전송/취소.
- 소셜 연동 해제 시 최소 1개 로그인 수단 보장(전부 해제 차단).
