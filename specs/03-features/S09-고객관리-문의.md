# S09 고객관리 = 고객 + 문의 (2026-10-04)

고객관리는 **고객**(중개사가 쓰는 고객 기록)과 **문의**(빌탐정으로 들어온 문의) 두 표다. 매물과 잇지 않는다 —
찾은 매물을 고객에 붙이지 않는다. 고객의 **조건**은 매물 탐색을 그 조건으로 여는 열쇠일 뿐이다.

## 0. 두 가지 「고객」

| | 고객 프로필 | 고객(중개사 기록) |
|---|---|---|
| 누가 쓰나 | 고객 본인(빌탐정 계정) | 중개사 |
| 누구 것 | 고객 계정 | 팀 |
| 생기는 길 | 마이페이지 | 직접 등록(전화 · 외부 · 기존 고객) · 문의에서 「고객으로 등록」 |
| 관계 | 문의할 때 사본(배경 + 조건)이 넘어간다 | 그 사본으로 **처음 한 번** 칸을 채운다. 그 뒤로는 따로 간다 |

두 쪽의 칸 이름은 같다 — 미리 채울 때 그대로 옮겨진다.

## 1. 고객 = 성격 + 조건

**성격(사람)** — `app.buyers` 칸. 중개사가 쓰던 고객 엑셀 열 그대로

| 엑셀 열 | 칸 | |
|---|---|---|
| 긴급도/찐 | `grade` 확실 · 보통 · 관망 | 있음 |
| 성함 · 전화 | `name` · `phone` | 있음 |
| 시드 | `equity_won` | 있음 |
| 개인/법인 | `is_corp` | 있음 |
| 시세차익/수익률 | `goal` 시세차익 · 수익률 · 실사용(여럿) | 새로 |
| 건축의사 | `build_intent` 있음 · 없음 · 모름 | 새로 |
| 매수시기 | `timing` 3개월 안 · 6개월 안 · 1년 안 · 미정 | 새로 |
| (매입 경험) | `experience` 처음 · 보유 경험 — 이해도는 뺐다(10-04, 매입 경험이 더 직관적) | 새로 |
| 희망매매가 | `budget_min` · `budget_max`(두 칸, 같으면 정해진 값) · `budget_any` 상관없음 | 새로(0216 · 0217) |
| 원하는 지역(입지) | `regions` 구 여럿 — **조건과 따로** 둔다(10-04). 서로 옮기거나 맞추지 않는다 | 새로 |
| 특징: 광고매물 | `prefer_ad` 광고 매물 선호 | 새로 |
| 비고 | `memo` | 있음 |
| (계정) | `account_id` — 빌탐정 고객 계정과 잇기. 같은 계정의 문의는 한 고객에 붙는다 | 새로 |

**조건(건물)** — 고객에 **저장한 조건**을 붙인다(아래 §3). 탐색 필터와 같은 꼴이라 누르면 바로 검색된다

| 엑셀 열 | 탐색 필터 칸 |
|---|---|
| (희망매매가는 성격 칸 — 새 조건을 만들 때 매매가에 한 번 미리 넣는다) | 매매가 |
| (원하는 지역은 성격 칸 — 조건의 지역은 그 검색의 범위) | 지역(구 · 동) · 그린 영역 |
| 대지면적 or 연면적 | 대지면적 · 연면적 |
| 평수/몇층 | 지상 층수 |
| 엘베 · 주차 | 엘리베이터(대) · 주차(대) |
| 수익률 | 수익률 |
| 특징: 역세권 · 건물 컨디션 · 공실 리스크 | 역과의 거리 · 사용승인일 · 리모델링 경과 · 공실 |
| (매물 종류) | 매물 유형 |

## 2. 화면

고객관리 툴바에 **고객 · 문의** 두 칸. 둘 다 매물관리 그리드 표 + 줄을 누르면 옆에 붙는 판.

**고객 표** — 열은 엑셀 순서: 긴급도 · 이름 · 조건(대표 요약 + 검색 아이콘) · 시드 · 목표 · 건축의사 · 개인/법인 · 시기 · 문의 수 · 비고.
툴바 오른쪽 **고객 등록**(매물관리의 매물 등록 자리) — 빈 고객 판이 열리고 칸을 바로 채운다.

**고객 판**
| 묶음 | 칸 |
|---|---|
| 성격 | 위 성격 칸 — 줄 문법(라벨 · 값, 클릭-편집, 선택 칩 재클릭 = 미지정) |
| 조건 | 붙은 조건마다 요약 한 줄 → 누르면 매물 탐색이 그 조건으로 열린다 · 연필(탐색에서 고치기) · ✕(떼기) · `+ 조건` |
| 문의 | 이 고객에 붙은 문의(문의날짜 · 유형 · 문의 매물 · 상태) — 누르면 문의 표로 |
| 메모 | 매물 모달과 같은 메모창 — 판 오른쪽 위 메모 버튼으로 열고 닫는다. 한 줄씩 쌓이고 쓴 사람 · 시각이 붙는다(원문 그대로) |

**문의 표** — 지금 그대로(문의날짜 · 상태 · 유형 · 이름 · 원하는 건물 · 문의 매물 · 전화 · 메모).
문의 판에 **고객으로 등록**: 같은 계정 고객이 있으면 그 고객에 붙이고, 없으면 새 고객을 만들며 사본으로 칸을 채운다.
문의 사본의 조건은 그 고객에 붙은 저장한 조건이 된다. 붙은 뒤엔 문의 판에 「고객 보기」.

## 3. 조건 — 저장한 조건에 고객을 붙인다

- 저장한 조건(`app.saved_searches`) 하나 = 조건 하나. **고객을 붙이거나 비워 둔다.**
  - 붙으면 그 고객의 조건이고 **팀 전체가 본다**(고객은 팀 것이라). 비우면 지금처럼 내 조건.
- 매물 탐색의 「저장한 조건」 목록에 붙은 고객 이름이 같이 선다(`김사장 · 강남 꼬마빌딩`).
- 매물 탐색에서 조건을 걸고 저장할 때 **고객을 고를 수 있다**(비워 두면 내 조건).
- 고객 판 · 표에서 조건을 누르면 `/explore` 가 그 조건으로 열린다(지금 매수자 조건과 같은 길).
- 옛 매수자 조건 표(`buyer_conditions`, 0건)는 저장한 조건으로 합치고 지운다.

**고객 프로필의 조건(고객 쪽)** — 고객도 매물 찾기에서 건 조건을 자기 프로필에 저장한다(같은 표, 고객 계정 것).
문의할 때 배경과 함께 조건도 사본으로 넘어간다(동의한 경우). 「고객으로 등록」하면 그 고객에 붙은 조건이 된다.

## 3-1. 고객 프로필 화면(고객 마이페이지 · 프로필 탭)

중개사 고객 판과 **같은 칸 · 같은 순서 · 같은 그리드 줄**. 고객이 적은 칸이 중개사 판에서 같은 자리에 선다.
라벨도 같다 — 「시드」를 고객 화면에서도 쓴다(10-04, 「자기자본」보다 덜 낯설다).

**원하는 것** — 무엇을 찾는가
| 줄 | 고르는 법 |
|---|---|
| 희망매매가 | 최소 ~ 최대 두 칸(억) + 상관없음 |
| 목표 | 시세차익 · 수익률 · 실사용(여럿) |
| 원하는 지역 | 구 25칸(여럿) |
| 매수 시기 | 3개월 안 · 6개월 안 · 1년 안 · 미정 |
| 건축의사 | 있음 · 없음 · 모름 |

**나에 대해** — 사람의 형편
| 줄 | 고르는 법 |
|---|---|
| 개인/법인 | 칸 둘 |
| 시드 | 클릭-편집(억) |
| 매입 경험 | 처음 · 보유 경험 |
| 메모 | 클릭-편집(여러 줄) |

**원하는 건물(저장한 조건)** — 매물 찾기에서 「조건 저장」한 것. 줄마다 요약 한 줄, 누르면 매물 찾기가 그 조건으로 열린다 · ✕ 지우기.
관심 탭의 「저장한 검색조건」을 이리로 옮긴다(관심 탭엔 저장한 매물만).

중개사 판에만 있는 칸(긴급도 · 광고 매물 선호)은 고객 쪽에 없다.

**중개사가 볼 수 있는 칸**
| 칸 | 구해요(익명 · 모든 중개사) | 문의(받은 중개사 한 곳 · 동의한 경우) |
|---|---|---|
| 희망매매가 · 목표 | 보임 | 보임 |
| 원하는 지역 · 매수 시기 · 건축의사 | 안 보임 — 익명 목록은 지금 두 칸이 딱 좋다(10-04, 많으면 복잡) | 보임 |
| 나에 대해 · 저장한 조건 | 안 보임 | 보임(문의 순간 사본) |

공개 여부를 칸마다 고르게 하지 않는다(10-04) — **민감한 정보가 아니면 공개**. 프로필 칸은 모두 민감 정보가 아니라
문의에선 전부 넘어간다(연락처처럼 문의 동의 한 번으로). 민감한 칸이 새로 생기면 그때 따로 정한다.

## 4. 스키마

| 표 | 바뀌는 것 |
|---|---|
| `buyers` | 더함: `goal text[]` · `build_intent` · `timing` · `experience` · `regions text[]` · `prefer_ad bool` · `account_id` · `budget_min` · `budget_max` · `budget_any`. 뺌: `literacy` |
| `saved_searches` | 더함: `team_id` · `buyer_id`(붙은 고객, 비우면 내 조건). 옛 `buyer_conditions` 합치고 지움 |
| `customer_profile` | 고객 쪽 배경 — 칸 이름을 고객 성격과 맞춤. 더함: `is_corp` · `budget_any`. 뺌: `literacy` |
| `inquiries` | 더함: `wants_snap`(문의 순간 고객 조건 사본). 고객과 잇는 칸은 `buyer_id`(이미 있음) |

문의 상태는 미확인 · 상담중 · 종료 그대로(0213).

## 5. 이번에 안 하는 것 · 다른 곳에서 하는 것

- 담은 매물 · 투자 가정(옛 매수자 기능) — 매물과 잇는 기능이라 고객 판에서 뺀다(표의 데이터는 둔다).
  매물 모달 계약 탭의 매수자 고르기는 이 고객 목록에서 고른다.

- 엑셀의 「광고추천」 열 — 뺀다(10-04). 필요한 말은 메모에 쓴다.
- 엑셀 가져오기 — 이 화면에 만들지 않는다. **모델(빌탐정 AI)의 스킬**로 만든다(10-04): 올린 엑셀의 열을 위 성격 · 조건 칸에 맞춰
  고객과 저장한 조건으로 넣는다.
