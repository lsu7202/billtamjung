## 1. 목적/역할
- 한 건물(대표지번)의 **모든 데이터를 한 화면**에 — 조회·업무관리·집단지성·산출물(보고서)의 허브.
- [[S01-매물통합검색]]에서 진입하는 실무의 중심 화면.

### 1.1 ★ 데이터 계층 (S02 전체를 관통하는 원칙)
> 상세·확정 규칙은 메모 `data-edit-architecture` 참조.

| 계층 | 소유 | 내용 | 원칙 |
|---|---|---|---|
| **① 공공 마스터** | 시스템 · read-only | 건물·토지·규제·공시지가·교통 원천 | **불변.** 유저 수정 절대 반영 안 됨 |
| **② 유저 오버레이** | 계정(+팀 공유) | 마스터 위에 개인이 **덮는 값**(정정·입력) | 화면값 = 마스터 + **내 오버레이**. **마스터에는 영향 없음.** 단 공공필드 정정값은 **수정이력 분포(§4.3)로 전체 유저에게 노출**되어 힌트가 된다(사적 레이어는 제외) |
| **③ 커뮤니티(전체 공유)** | 전 유저 | **위키**(특이사항)·**광고가**(시세 점) | 마스터 정정 아님, **새 글/시세 추가**·동의(👍)·신고 |
| ※ 시스템 추정 | 시스템 · read-only | **실거래사례**(추정 매칭) | "추정" 고지. 유저 오버레이 없음 |

- [규칙] **핵심: 마스터는 절대 안 바뀐다.** 유저가 고친 건 자기(+팀) 오버레이일 뿐. 다수결·전체반영 없음.
  - ※ "남에게 영향 없음"은 **마스터·타인의 값을 바꾸지 않는다**는 뜻이지, 보이지 않는다는 뜻이 아니다. 공공필드 정정은 §4.3 분포로 노출된다.
- [규칙] **관리 단위 = 대표지번**(부속 필지 자동 포함, [[S01-매물통합검색]] §3.0). 필지별 값은 관련필지에서 열람(§3.6).

### 1.2 ★ 수정 모드 (필드별 — `04-data/data-overview.md`에 명시)
- **원칙: UI에 노출되는 필드는 전부 수정 가능**(오버레이). 잠금 없음 — 오버레이는 개인/팀 전용이라 마스터·타인 무영향.
- **내부 식별자(PNU·좌표·폴리곤·법정동코드·주소)** = UI 비노출 → 수정 논외.

| 모드 | 필드 | 규칙 |
|---|---|---|
| **✏️ 직접입력** | 대장현황·용도지역·공시지가·규제·지목 등 원본값 + 사적(업무·상세·임대·매매가·메모) | 유저 입력 → 오버레이(②) |
| **🔀 계산 or 입력** | 수익률·자기자본·평단가·여유분·법정치·역거리·총공시지가·상승률 등 파생 | 자동계산 기본, **직접입력도 허용**(강제 계산 X). 직접입력값 있으면 우선. **자동/수동 배지 없음** |

## 2. 진입 · 이탈
- **진입**: [[S01-매물통합검색]] 행/핀 → 이 화면(건물 PK/PNU). 부속지번 검색도 대표 건물로 귀결.
- **이탈**:
  - `매물 분석하기` → **매물분석보고서**(PPT, 크레딧 소모) → [[R-보고서]].
  - `브리핑 자료` → **브리핑 PPT**(크레딧 소모) → [[R-보고서]].
  - **화면 이탈**: GNB `검색` 또는 브라우저 뒤로 → [[S01-매물통합검색]](결과·스크롤 복원).
    ⚠️ ~~하단 `←` 뒤로가기~~ **정정(2026-07-19)**: 하단 `← → ↺`는 **데이터 수정 undo/redo/복원 전용**이며 화면 이동이 아니다(§5). 같은 버튼이 화면 이탈과 데이터 undo를 겸할 수 없어 분리.
- [규칙] **상세 조회 자체는 무크레딧.** 크레딧은 산출물(보고서·브리핑)에만.
- [규칙] **★ 네비게이션 공통 규칙**: 매물·필지 **주소/행은 어디서든 클릭 = 그 대상의 상세로 이동**(주변시세 comps·관련필지·[[R-보고서]] 유사사례 전부). 부속지번은 대표건물로 귀결([[S01-매물통합검색]] §3.0).

### 3.5 층별 임대정보 [② 사적 오버레이 · 팀 공유, 프리필+수기]  *(레이어 확정 2026-07-19)*

> **레이어 = ② 유저 오버레이(사적).** ③ 커뮤니티(위키·광고가)가 **아니다.**
> - **이 표는 내(팀) 것.** 다른 유저·다른 팀의 입력이 여기 섞이지 않는다. 병합·다수결 없음.
> - **단 내가 넣은 행은 [[S03-주변시세]]에서 다른 유저의 comps로 주소와 함께 노출된다.** (반대로 내 S03 comps에도 남의 행이 뜬다.)
> - 즉 **저장은 사적, 조회는 공용.** 노이즈 정제는 저장 시점이 아니라 **S03 소비 시점**(이상치 표시·체크해제)에 한다.
> - 근거: 공동 편집 모델이면 타인의 오입력(예 "1층 201호")이 내 표를 오염시키고, 콜드스타트에선 1인 입력이 곧 최다값이 되어 사실로 굳는다.

- [규칙] 표: 층·호실·**용도**·전용면적·**계약면적**·보증금·임대료·관리비·**상태(공실 토글)**. `＋ 호실 추가`로 행 추가.
- [데이터] **층·용도·전용면적 = 층별개요 프리필**, 호실·**계약면적**·금액·공실 = 수기. 층구분 7값·공실 3값(`data-overview` G4).
- [규칙] **평당 시세의 "평" = 계약면적 기준**(전용 아님) — [[S03-주변시세]] 평당 보증금/임대료와 정합.
- [규칙] 합산값이 §3.4 총보증금/임대료/관리비·총공실·수익률에 반영.

#### ★ 필지 셀렉터 *(확정 2026-07-19 — 관련필지 모달 폐기)*
- [규칙] 건물이 여러 필지에 걸치면(다필지) **토지정보 섹션 상단에 필지 탭**을 띄운다. 선택 시 **토지정보 · 규제·특례 · 공시지가** 3개 블록이 그 필지 값으로 전환된다.
- [규칙] **건물 단위 값은 바뀌지 않는다** — 건물정보·금액정보·층별임대·실거래·광고·입지 전부 고정.
- [규칙] 기본 선택 = **대표필지**. 단일 필지면 탭 대신 "단일 필지 (부속지번 없음)" 표기.
- [규칙] **각 필지는 자기 값을 그대로 표시**(합산·평균 안 함). 필지마다 값이 다를 수 있다 — 실측: 다필지 2,521동 중 **220동이 필지별 공시지가 상이**, 최대 17배 차(도곡동 산21).
- ~~관련필지 모달 → 필지 행 클릭 → 필지 상세 화면~~ **폐기.** 별도 필지 상세 화면을 만들지 않는다.
  - 근거: 부속필지의 **99.2%는 `buildings`에 자기 레코드가 없어** 이동할 화면이 애초에 존재하지 않는다(강남 실측: 부속 3,267개 중 자기 건물 보유 25개).
  - [예외] 그 필지에 **다른 건물**이 있으면(0.77%) 네비게이션 공통 규칙(§2)대로 그 건물 S02로 이동.

#### ★ 규제·특례의 2레벨 구조 *(확정 2026-07-19)*
| 레벨 | 값 | 용도 |
|---|---|---|
| **건물 요약** | 그 건물이 앉은 **전 필지의 OR 집계** | "이 건물이 규제에 걸리는가"를 한눈에 |
| **필지 상세** | 그 필지의 실제 규제 | 필지 셀렉터로 "어느 필지가 걸렸나" 확인 |
- [규칙] 건물이 여러 필지에 걸치면 **어느 한 필지라도 규제에 걸릴 때 건물이 영향을 받는다** → 요약은 **OR**가 맞다. 구역명이 서로 다르면 `" / "`로 병기.
- ⚠️ **과거 결함**: 건물 규제를 **대표필지 것만** 가져와 부속필지 규제가 누락됐다. 강남 실측 **48동 교정**(삼성동 142-5 문화재보존, 압구정동 397 경관지구 등). `build_gangnam.py reg_or()` 수정 완료.

> 내가 과거에 어떻게 고쳤는지 되짚는 개인 로그가 **아니다**. 이전 값을 보는 화면이 아니다.

- [규칙] **표시 = 값별 분포.** 필드마다 "어떤 값을 몇 명이 갖고 있나"를 집계해 보여준다.

- [규칙] **범위 = 전체 유저.** 팀 내부로 한정하지 않는다. 마스터 정정의 집단지성 신호이므로 모수가 클수록 유용하다.
- [규칙] **마스터는 여전히 불변.** 분포가 아무리 쏠려도 자동 반영·다수결 확정 없음. 참고 힌트일 뿐이며 채택은 각자 판단.

- [규칙] **익명 집계 — 작성자를 표시하지 않는다.** 값과 인원수만 보여준다. 누가 그 값을 넣었는지는 노출되지 않으므로 최소 표본(n) 제한이 필요 없다.
- [규칙] **분포 공개 대상 = 공공 마스터 정정 필드만**(대장현황·용도지역·공시지가·규제·지목 등).
  **사적 레이어는 절대 분포에 넣지 않는다** — 업무(§4.1, 소유자·연락처·협조도)·메모(§4.4)·금액/임대 등 사적 입력값.

### 5.1 되돌리기 모델 *(확정 2026-07-19)*

**undo/redo(`←` `→`)는 폐기했다.** 오버레이가 팀 공유인데 undo 스택이 개인 세션이면 성립하지 않기 때문이다.

- **폐기 사유 — 동시 수정 시 남의 작업이 소실된다**
  ```
  14:00  나     주차 4대 → 5대      (팀 화면: 5대)
  14:01  박실장  주차 5대 → 6대      (팀 화면: 6대)
  14:02  나     undo                → 내 스택은 "5→4"만 알아 6대가 4대로 덮임 (lost update)
  ```
  공유 데이터의 undo를 제대로 하려면 OT/CRDT급 설계가 필요한데 이 규모엔 과하다.

- **대체 = 되돌리기 2단**

  | 수단 | 범위 | 위치 |
  |---|---|---|
  | **필드별 되돌리기** | 그 필드 하나만 마스터 원본으로 | 수정된 필드에 호버 → `↺` |
  | **전체 되돌리기** | 이 매물의 내 오버레이 전부 제거 | 하단 툴바 `↺ 전체 되돌리기` |

- [규칙] **수정된 필드는 시각적으로 구분**한다(값 색상 + 점 표시). 수정이력 탭이 남의 값 분포로 바뀌었으므로, **"내가 뭘 고쳤나"는 필드 자체가 표시**한다.
- [규칙] 되돌리기는 **항상 마스터 원본으로만** 간다. 중간 단계로 되감지 않는다 → 동시 수정과 무관하게 항상 안전한 목적지.
- [규칙] 되돌리기 툴팁에 마스터 원본값을 표기한다. 예) `마스터 원본(4대)으로 되돌리기`
- [규칙] **주변시세 curation(체크 해제·× 삭제)의 복구** = 해당 블록의 `재조회`. 상권 조건으로 comps를 다시 불러오면 체크 상태가 초기화된다. 오버레이 되돌리기(`↺`)와는 별개 경로다 — comps는 조회 결과이지 마스터 필드가 아니기 때문.
- [규칙] **팀원이 고친 필드도 되돌릴 수 있다** *(확정 2026-07-19)*. 오버레이가 팀 전체 공유이므로 되돌리기도 팀 전체가 가능해야 일관된다. 목적지가 항상 마스터 원본으로 고정이라 되돌려도 안전하다.

### 5.2 편집 인터랙션 · 검증 · 실패 처리 *(신설 2026-07-19 — 기존 명세 전무)*

#### 편집 방식
- [규칙] **인라인 편집.** 값을 클릭하면 그 자리에서 입력 상태가 된다. 모달을 띄우지 않는다.

- [규칙] **확정 = blur 또는 Enter. 취소 = Esc**(입력 전 값으로 되돌림).
- [규칙] **자동 저장** — 확정 즉시 서버 반영. 저장 버튼 없음.

#### 검증
- [규칙] 저장 전 **타입·범위 검증**을 하고, 실패하면 **인라인 오류 메시지**를 필드 아래 표시한다(값은 입력칸에 유지).

| 대상 | 규칙 |
|---|---|
| 면적 (대지·연·건축·전용·계약) | `> 0` · 상한 없음 |
| 금액 (매매가·보증금·임대료·관리비·광고가) | `≥ 0` 정수(원) · 음수 금지 |
| 비율 (건폐율·용적률·수익률) | `≥ 0` · 건폐율 `≤ 100` |
| 층 | 건축물대장 규모(지상/지하) 범위 내 |
| 날짜 (사용승인일·대수선·확인일) | 유효 날짜 · **미래 날짜 금지** |
| 개수 (엘리베이터·주차·실거래횟수) | `≥ 0` 정수 |
| enum 전 필드 | 정의된 값만(`enums.md`) |

#### 저장 실패
- [규칙] **낙관적 반영 후 롤백** — 입력 즉시 화면에 반영하고 서버 저장을 시도한다. 실패하면 **이전 값으로 되돌리고** 실패를 알린다.
- [규칙] **네트워크 실패는 자동 재시도**(짧은 백오프 2~3회). 그래도 실패하면 `저장 실패 · 다시 시도` 표시.
- [규칙] **입력값을 잃지 않는다** — 실패해도 사용자가 친 값은 입력칸에 남겨 재시도할 수 있게 한다.
- [규칙] 권한 없음(예: 남의 팀 데이터)으로 실패하면 재시도하지 않고 사유를 표시한다.
- ⚠️ 자동 저장 UI에서는 **실패를 조용히 넘기면 사용자가 저장된 줄 안다.** 실패는 반드시 눈에 보여야 한다.

### 5.3 면적 입력의 단위 해석 *(확정 2026-07-19 — 미정 시 데이터 오염)*

**규칙: 입력값은 "지금 화면에 표시된 단위"로 해석하고, 저장은 항상 ㎡로 변환한다.**

```
평 모드에서 "745.6" 입력  →  745.6평으로 해석  →  2,464.8㎡ 저장
㎡ 모드에서 "2464.8" 입력 →  2,464.8㎡로 해석  →  2,464.8㎡ 저장
```

- [규칙] **환산 계수 = 3.305785㎡/평** (역: 0.3025평/㎡). `data-overview` 저장 단위 원칙과 동일.
- [규칙] **입력 필드 옆에 현재 단위를 항상 표기**한다(`745.6 평`). 단위가 안 보이는 숫자 입력칸을 만들지 않는다.
- [규칙] **입력 중 단위를 토글하면 입력값을 환산해 다시 채운다.** 숫자를 그대로 두고 단위만 바꾸면 값이 3.3배 틀어진다.
- [규칙] **저장은 항상 ㎡.** 평으로 저장하지 않는다 — 평은 무리수 환산이라 왕복 시 오차가 누적된다.
- [규칙] 표시 반올림(소수 1자리)은 **표시에만** 적용하고 저장값은 원본 정밀도를 유지한다. 745.6평으로 보이는 값을 다시 저장해 2,464.8㎡가 2,464.7㎡로 밀리는 일이 없어야 한다.
- **적용 대상**: 대지면적·연면적·건축면적·용적률산정연면적·토지면적·전용면적·계약면적 등 **모든 면적 필드**.

> **왜 못 박는가**: 이 규칙이 없으면 "평 모드에서 71.9를 고쳤는데 71.9㎡로 저장"되는 식의 오염이 발생한다. 되돌리기로도 복구되지 않는다(마스터가 아니라 오버레이 값이 틀린 것이므로).

## 6. 상태 · 규칙
- [규칙] 파생값(🔀 모드)은 원천 수정 시 자동 재계산 — **단 직접입력값이 있으면 그 값 우선**(§1.2).
- [규칙] 유저 수정 = 마스터 불변, **오버레이만**(팀 공유범위). 커뮤니티(위키·광고가)는 전체 공유·동의(👍)·신고. 실거래=시스템 추정 read-only.
- [규칙] **무료/유료 경계**: 앱(S02)은 **raw 데이터 + 유저 curation**(주변시세 조회·다듬기 포함) 무료. **분석 synthesis(가치점수·적정매매가·협의금액·예상수익률)는 S02에 안 뜸 → 보고서 전용**([[R-보고서]]).
- [규칙] 크레딧: 조회·수정·주변시세 분석 무료. **보고서·브리핑만 소모**([[S0M-마이페이지]] §3.2).
