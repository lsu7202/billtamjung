> **역할**: 가공(적재) 전에 **어떤 원본이 어떤 키로 붙는지**를 확정하는 지도. 실제 컬럼 정의=`data-overview.md`·`mart-layout.md`·`codes-vworld.md`.
> 상태: ✅ 실증 검증 · 🟡 규칙만(코드 미작성) · ❓ 미검증. 2026-07-13.

## 1. 두 개의 축 (키) — 이게 핵심

빌탐정 데이터는 **서로 다른 두 키**로 나뉘고, 그 둘을 잇는 게 관건.

```
        ┌─────────── PNU (필지, 19자리) ───────────┐   ┌──── 관리대장PK (건물) ────┐
  토지특성 · 연속지적도 · 용도지역 · 개발제한 · 공시지가        표제부 · 층별개요 · 전유부
                          │                                        │  (PK 100% ✅)
                          │                                        │
          총괄표제부 · 인허가 ── PNU 조립으로 붙음(PK 아님!) ────────┘
                          │                                        │
                          └──── PNU 생성식으로 연결 ✅ 96.8% ───────┘
                                (건물 마트 → PNU 조립, 실증 완료)
```

- **PNU 축** = 땅. 서로 간 조인은 **99.9% 실증 완료** ✅ (토지특성 A1 ↔ 지적도 PNU).
- **관리대장PK 축** = 건물. 단, **표제부·층별개요·전유부만** 이 PK를 공유(100% ✅). **총괄표제부·인허가는 PK가 다름(매칭 0%) → PNU로 붙음.**
- **두 축의 연결** = 건물 마트에서 **PNU를 조립**해 땅에 붙임 → **✅ 96.8% 실증** (아래 §4).

## 3. 관리대장PK 축 (건물) — 조인 키가 파일마다 다름 ✅ 검증됨

| 원본 | 키 | 준다 | 조인 실측 |

| **층별개요** djy_04 | 관리대장PK(idx0) | 층별 용도·면적 (층별 임대정보 프리필) | 표제부 PK **100%** ✅ (586,176/586,180) |

| **인허가** kcy_05/10/11/15 | **PNU**(idx2,3,4,5,6) — PK 아님 | 대수선일·착공/사용승인 등 | 토지 PNU **97.7%** ✅ (kcy_15) |

⚠️ **핵심 정정**: 마트가 관리대장PK로 균일 조인된다는 가정은 틀림. **PK를 공유하는 건 표제부·층별개요·전유부뿐**(100%). 총괄표제부·인허가는 별도 키 체계(총괄 idx0=6자리, kcy idx0=13자리)라 **PNU 조립으로만** 표제부·토지에 붙는다.

**총괄표제부 djy_02 컬럼 확정**: 주소(10 시군구·11 법정동·12 대지구분·13 번·14 지) · [24] 대지면적 · [26] 건폐율(%) · [28] 연면적 · [29] 용적률(%) · [30/31] 주용도코드/명. 64필드 100% 채움.

**규칙 (건폐율·용적률·대지면적 소스)**: 표제부의 PNU ↔ 총괄표제부의 PNU 조인 → **총괄 있으면(다동 단지) 총괄값, 없으면(단독 동) 표제부값.** 한 단지의 여러 동은 같은 PNU를 공유하므로 총괄값이 동 전체에 매핑됨.

→ **건물 마스터(관리대장PK 1행) ✅ 조립 완료** (`build_building_master.py` → 586,343동). PK 유일(중복 0)·연면적/주용도 100%·사용승인일 94.7%. 대지면적/건폐율/용적률은 표제부에 ~57%만 채워짐(집합·다동단지 결측) → **폴백 체인**(총괄 PNU 우선 → 표제부 자체 → 대지면적만 토지특성). 결과: **토지 연결 95.5% · 대지면적 95.7% · 용적률 직접값 63.5%**(잔여는 F-15 파생 대상, 결측 아님). 출처: 표제부 354,849·토지특성 179,603·총괄 51,891.

**통합 뷰 검증**: 건물(연면적·층수·용적) + 토지(용도지역·이용상황·공시지가·지세·개발제한)가 PNU로 정확 조인됨(스팟체크 통과). 단독필지는 표제부 대지=토지 A12 일치, 다동단지는 총괄 대지(단지전체)>토지 A12(필지) — 예상된 그레인 차이.

## 4. 두 축의 연결 = PNU 생성식 ✅ 실증 완료 (96.8%)

건물 마트엔 PNU가 통째로 없고 **조각**으로 있음:
```
PNU(19) = 시군구코드(5) + 법정동코드(5) + 대지구분(1) + 번(4) + 지(4)
  표제부   idx8          idx9           idx10         idx11   idx12
  총괄     idx10         idx11          idx12         idx13   idx14
  인허가   idx2          idx3           idx4          idx5    idx6
```
✅ **검증됨**: 대지구분 매핑 **0→1(대지)·1→2(산)**·번/지 4자리 zero-pad로 조립 → 토지특성 PNU와 실매칭:
- **표제부 → 토지 96.8%** (496,947/513,595) · **총괄 → 토지 85.5%** · **인허가 → 토지 97.7%**
- 대지구분 분포: 0=581,665 · 1=4,125 · 2=553 (대부분 대지)
- 미매칭 잔여(~3%)는 신축 미등재·지번 정정·폐합 등 → 주소 문자열 폴백으로 보완 예정.

**결론: 건물↔토지 통합 가능.** 별도 주소 매칭 없이 PNU 조립만으로 96.8% 연결.
