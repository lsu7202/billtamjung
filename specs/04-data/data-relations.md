# 데이터 관계도 (원본 → 통합 매물 · 키·조인)

> **역할**: 가공(적재) 전에 **어떤 원본이 어떤 키로 붙는지**를 확정하는 지도. 실제 컬럼 정의=`data-overview.md`·`mart-layout.md`·`codes-vworld.md`.
> 상태: ✅ 실증 검증 · 🟡 규칙만(코드 미작성) · ❓ 미검증. 2026-07-13.

---

## 1. 두 개의 축 (키) — 이게 핵심

빌탐정 데이터는 **서로 다른 두 키**로 나뉘고, 그 둘을 잇는 게 관건.

```
        ┌─────────── PNU (필지, 19자리) ───────────┐   ┌──── 관리대장PK (건물) ────┐
  토지특성 · 연속지적도 · 용도지역 · 개발제한 · 공시지가        표제부 · 총괄표제부 · 층별개요 · 전유부 · 인허가
                          │                                        │
                          └──────── PNU 생성식으로 연결 ❓ ────────┘
                                   (건물 마트 → PNU 조립, 미검증)
```

- **PNU 축** = 땅. 서로 간 조인은 **99.9% 실증 완료** ✅ (토지특성 A1 ↔ 지적도 PNU).
- **관리대장PK 축** = 건물. 마트 파일끼리 이 PK로 연결.
- **두 축의 연결** = 건물 마트에서 **PNU를 조립**해 땅에 붙임 → **❓ 미검증** (아래 §4).

## 2. PNU 축 (토지) — 조인 ✅ 검증됨

| 원본 | 키 | 준다 | 조인 방식 |
|---|---|---|---|
| **토지특성** AL_D194 | PNU(A1) | 지목·면적·이용상황·도로접면·지형형상·지세 | 기준 테이블 |
| **연속지적도** LSMD_LDREG | PNU | 필지 폴리곤(지오메트리) | PNU 직접 조인 (99.9% ✅) |
| **개별공시지가** AL_D150 | PNU(A0) | 연도별 공시지가 | PNU 직접 조인 (연도판 4개 UNION) |
| **용도지역** UQ111 | 폴리곤 | UQA 코드 | **공간 교차**(지적도 폴리곤 ∩) → PNU별 N행 🟡 |
| **개발제한** UD801 | 폴리곤 | 해당 여부 | **공간 교차**(지적도 ∩) → PNU별 비중 🟡 |
| **DEM/지세** | (지세=A19) | 경사 | 지세는 토지특성 내장 ✅ / DEM은 공간 zonal 🟡 |

→ **토지 마스터(PNU 1행)** = 토지특성 + 공시지가 시계열 + 공간분석 산출(용도지역 대표·법정치·개발제한).

## 3. 관리대장PK 축 (건물) — 마트 내부 조인 🟡

| 원본 | 키 | 준다 | 상태 |
|---|---|---|---|
| **표제부** djy_03 | 관리대장PK(idx0) | 연면적·건폐/용적·층수·승강기·주차·주용도·기타용도·사용승인일 | ✅ 컬럼 확정 |
| **총괄표제부** djy_02 | 관리대장PK(추정) | **다동 단지의 대지면적·건폐율·용적률** | 🟡 64컬럼 미파싱 |
| **층별개요** djy_04 | 관리대장PK(idx0) | 층별 용도·면적 (층별 임대정보 프리필) | ✅ 컬럼 확정 |
| **전유부** djy_09 | 관리대장PK | 동·호 | (미사용 결정) |
| **인허가** kcy_05/10/11/15 | ❓ | 대수선일·주차 등 | 🟡 미파싱 |

**규칙 (건폐율·용적률·대지면적 소스)**: 관리대장PK로 표제부↔총괄표제부 조인 → **총괄 있으면(다동 단지) 총괄값, 없으면(단독 동) 표제부값.** ← djy_02 파싱 후 확정.

→ **건물 마스터(관리대장PK 1행)** = 표제부 + 총괄표제부(대지·건폐·용적) + 인허가(대수선) + FK(PNU).

## 4. 두 축의 연결 = PNU 생성식 ❓ 최우선 검증 대상

건물 마트엔 PNU가 통째로 없고 **조각**으로 있음:
```
PNU(19) = 시군구코드(5) + 법정동코드(5) + 대지구분(1) + 번(4) + 지(4)
          djy_03 idx8    idx9          idx10        idx11   idx12
```
⚠️ **미검증 지점**: 대지구분코드(0 대지/1 산/2 블록) ↔ PNU 표준(1 대지/2 산)의 **매핑**. → 생성한 PNU가 토지특성 PNU와 실제 매칭되는지 **표본 대조 필요.** 이게 되면 **건물↔토지 통합** 완성, 안 되면 주소 기반 폴백.

## 5. 유저/집단지성 (원본 무관 — 앱 생성)

| 데이터 | 붙는 곳 | 키 |
|---|---|---|
| 층별 임대정보(호실) | 건물(층별개요 프리필 위) | 관리대장PK → 층 → 호실 |
| 광고가 | 건물 | 관리대장PK |
| 매각(수기 B) | 건물 | 관리대장PK |
| 위키·수정이력 | 건물/필지 | 각 대상 |
| 내 매물·CRM (사적) | 건물 | 관리대장PK + 유저/팀 |

## 6. 시장 데이터 (건물에 느슨 연결)

| 데이터 | 붙는 방식 |
|---|---|
| 주변 매각시세(A) | **동 단위** — 건물 특정 안 함 (지번 없음) |
| 추정 매각이력(A+) | 동+대지+연면적+승인연도+지번앞자리 매칭 → 건물(~80% ✅ 실측) |

## 통합 순서 (이 관계도 기준)

1. **PNU 생성식 검증** ❓ — 건물↔토지 연결 가능 여부 결정 (최우선, 안 되면 전체 설계 바뀜)
2. **총괄표제부(djy_02) 파싱** → 건폐율·용적률 소스 규칙 확정
3. **인허가(kcy) 파싱** → 대수선일 등 위치 확정
4. 토지 마스터 조립(공시지가 UNION) + 공간분석(용도지역·개발제한)
5. 건물 마스터 조립 + PNU로 토지 붙이기
6. 교통 거리 계산 · 매각 매칭
7. → 통합 매물 뷰 완성 → **원하는 상태인지 검증** → 필드별 출처 확정 → schema.md
