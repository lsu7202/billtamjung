## 2 · 처리함 (2026-08-09)

| 항목 | 무엇을 했나 |
|---|---|
| **주변 실거래 조건** | `comp_filter` 오버레이 신설 — 기간(1·2·3·5·10년)·가격 하한/상한. 매물상세와 리포트가 같은 값을 읽는다. 기본은 현행(5년·무제한)이라 안 건드린 리포트는 값이 안 변한다.<br>실측(종로2가 71-6): 기본 57건 **8억~6,215억** → 5년+100억↑ 26건 102억~6,215억 → 5년+50~200억 33건 51억~200억 |
| **투자분석 부대비용** | `대출액 = 총투자비 − 자기자본`, `총투자비 = 매매가 + 부대비용`. 부대비용률 기본 5.7%(중개 0.9 + 취득세등 4.6 + 법무사 0.2), 화면에서 수정 가능. LTV는 담보가(매매가) 기준 유지 — 은행 정의와 맞춰야 상담에서 말이 안 어긋난다. 정본 **F-11b** |
| **불러오기 즉시 적용** | 「불러오기」가 그 자리에서 적용하고 닫는다. '적용' 버튼과 같은 `apply()` 한 길을 탄다 — 길이 둘이라 구 전체 승격 보정이 불러오기엔 빠져 있었다 |
| **저장조건 수정** | `PATCH /saved-searches/{id}` 신설(COALESCE 부분 갱신). 목록에 「이름」·「덮어쓰기」 |
| **그리기 다중 영역** | 프론트에서 배열로 쌓고 `mergeGeo()`로 MultiPolygon 하나로 합쳐 전송. `ST_Within(geom, MultiPolygon)`이 그대로 성립해 **백엔드 무변경**. 칩에서 영역 하나씩 삭제 |
| **첫 화면 = 내 매물** | 지역·영역이 없으면 `mine_only`로 내 매물 전체. '일반' 열은 서울 전체가 되어 안 돈다. `listings_claim` 부분 인덱스라 범위 조건 없이도 **68ms** |
| **금액 억 단위 입력** | `parseWon()` — `1500억`·`15억5000만`·`1500.1억`·콤마 원. 단위 없으면 원 그대로라 기존 입력법 유지. 해석 불가는 오류로 세운다(0으로 삼키지 않는다) |
| **전용면적 제거** | 한 줄이 아니었다 — 대장 층별면적이 전용면적이 아니라 **바닥면적**임을 실측(55.9만동, 옥탑 제외 95.2%가 연면적과 일치)하고 개념째 삭제. 마이그레이션 `0035_floor_area.sql`, 면적은 계약면적 하나 |
| **리포트 대지평단가** | 04 유사사례·스토리·표지 요약·결론 3축 전부 대지 기준. 표는 「대지 평단가 \| 연면적 평단가」 두 열. 정본 **F-09c**.<br>**적정가 산출식은 안 건드렸다** — 백테스트(MdAPE 17.5%) 무효화를 피했다. 산식이 이미 대지평단가법을 0.4 비중으로 쓴다 |
| **용적률 초과 표기** | `(현재 ÷ 법정 − 1) × 100` → **%p 차이**. 정본 F-09b·검색 필터·데이터사전은 처음부터 %p였고 리포트 한 곳만 어긋나 있었다 |

## 4 · 확인 필요

- ~~**"법정대비 10%가 아니라 77% 초과"**~~ → **해소(2026-08-09)**. 건물 데이터 문제가 아니라 **단위**였다.
