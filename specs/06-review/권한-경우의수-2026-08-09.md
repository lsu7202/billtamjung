# 권한(대표 ↔ 팀원) 경우의 수 · QA

> 2026-08-09. 현장 지적: **"담당자를 서로 뺏을 수 있다. 관리자가 담당인데 팀원이 바꿀 수 있다."**
> 정본 = `03-features/S0M-마이페이지.md` §3.5(선점) · §3.4(공유범위) · §3.3(역할)
>
> 역할은 둘뿐이다 — **대표(owner)** / **팀원(member)**.
> 경우의 수를 먼저 펼치고, 각각을 실제로 호출해 확인한다. 추측으로 고치지 않는다.

## 1 · 정본이 정한 규칙

| # | 규칙 | 근거 |
|---|---|---|
| R1 | 팀 내 1매물 = 1담당자. 이미 담당자가 있으면 **다른 팀원도 대표도** 자기 것으로 못 잡는다 | §3.5 |
| R2 | 팀원은 **자기 자신만** 담당자로 지정 가능 | §3.5 |
| R3 | **대표만** 재배정 가능(퇴사·이관) | §3.5 |
| R4 | **해제는 명시적 행위** — 담당자를 비우면 선점이 풀린다 | §3.5 |
| R5 | 담당자 퇴사·제외 → 그 매물은 **대표에게 자동 귀속**(고아 금지) | §3.5 |
| R6 | 전화번호·비밀메모 = **담당자 본인 + 대표만** (공유의 유일한 예외 2곳) | §3.4 |

| **R6c** | **못 보는 사람은 쓰지도 못한다** — 읽기·쓰기 경계를 같게 | 결정 2026-08-09 §3.2 |
| R7 | 그 외 매물 데이터·오버레이·업무탭·메모·위키 = 팀 전체 공유 | §3.4 |
| R8 | 팀 관리(초대·제외·팀명·사무소·로고) = **대표만** | §3.3 |

**누가 해제할 수 있는지**가 정해져야 하는데 정본에 없다. → §3에서 결정.

## 3 · 결정 — 해제 권한

정본의 R4("해제는 명시적 행위")는 **해제가 상태 변경의 부수효과로 일어나면 안 된다**는 뜻이지,
**아무나 해제해도 된다**는 뜻이 아니다. R1(선점)과 같이 읽으면 답은 하나다.

> **해제는 담당자 본인 또는 대표만 할 수 있다.**

이유 — 해제를 아무나 할 수 있으면 R1이 무의미해진다. 팀원이 `해제 → 내가 담당`을 두 번 눌러
남의 매물을 가져갈 수 있고, 그건 정본이 막으려던 바로 그 일이다(C13).

### 3.2 개인정보 — 매수자 연락처 · 쓰기 경계

정본 R6은 매물 소유자 전화번호만 말한다. 매수자 연락처는 S04에서 새로 생긴 필드라 규칙이 없었고,
그래서 팀 전체에 그대로 노출됐다. **같은 급의 개인정보를 한쪽만 막는 이유가 없다.**

> **매수자 연락처도 담당자 본인 + 대표만.**

그리고 읽기만 막으면 구멍이 남는다. 마스킹된 값(`010-****-8888`)을 보는 사람이
그 값을 그대로 저장하면 **진짜 번호가 덮여 사라진다.** `patch_biz`의 `owner_phone`에
쓰기 제한이 없어 실제로 가능했다.

> **못 보는 사람은 쓰지도 못한다.** 읽기 경계 = 쓰기 경계.

## 4 · QA 결과

`qa/app/qa_permissions.py` — 매 실행마다 대표1+팀원2로 새 팀을 만들어 표를 그대로 호출한다.
로컬 전용(가입을 열어 계정을 만든다).

### 4.1 처음 돌렸을 때 — **3건 뚫림**

| # | 증상 |
|---|---|
| **C9** | 팀원이 **대표의 담당을 해제**할 수 있었다(200, assignee→null) |
| **C13** | 「해제 → 내가 담당」 **2단계로 탈취 성공**(최종 담당=팀원) |
| V5 | 대표가 비밀메모를 못 봄 → **테스트가 틀렸다**(필드명 `text`→`body`). 앱은 정상 |

C9·C13이 현장에서 지적한 바로 그 문제다. 원인은 한 줄:

```python
if (target is not None and cur_assignee is not None
        and cur_assignee != target and user.role != "owner"):
```

`target is not None`이 앞에 있어 **해제(null)는 검사를 통째로 건너뛴다.**
선점 규칙(R1)이 있으나 마나가 된다.

### 4.2 개인정보 — 2건 더 나옴

| # | 증상 |
|---|---|
| **B2b** | 매수자 연락처가 **팀 전체에 원본 노출**(S04 신규 필드, 규칙 없이 만들었다) |
| **V7** | 매물 `owner_phone`에 **쓰기 제한이 없어** 마스킹된 값으로 원본을 덮을 수 있었다 |

### 4.3 고친 뒤 — **36/36 통과**

서버(`listings.claim`)에 해제 권한 검사를 넣었다.
```python
if (target is None and cur_assignee is not None
        and user.role != "owner" and cur_assignee != user.account_id):
    raise HTTPException(403, "담당자 본인 또는 대표만 해제할 수 있습니다")
```

화면(`Sidebar.BizTab`)도 같은 경계로 맞췄다 — 눌러도 거부될 컨트롤은 아예 안 보인다.

| 보는 사람 | 담당자 칸 |
|---|---|
| 대표 | 셀렉트(팀원 전체) + 「제거」 |
| 담당 본인 | 〃 |
| **다른 팀원** | **이름만**(셀렉트·제거 없음) |

거부되면 사유를 띄운다 — 눌렀는데 아무 일도 안 일어나면 고장으로 읽힌다.
