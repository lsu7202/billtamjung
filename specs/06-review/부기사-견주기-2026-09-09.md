# 부기사 견주기 — 탭별 기능·차이·따라갈 길 (2026-09-09)

> **왜 이 문서인가.** 중개사무소 대부분이 부기사가 만들어 준 프로그램을 쓴다.
> 중개인들이 **이미 그 화면 어법과 낱말에 적응해 있다.** 그래서 우리가 볼 것은
> 「무슨 기능이 있나」보다 **「사람들이 이미 익은 모양이 무엇인가」**다.
> 낯선 걸 새로 가르치는 비용을 줄이려면 익은 모양을 알아야 한다.
>
> **읽은 것**: 공개 가이드 전문(홈페이지·상업용·종합형·플랫폼), 가격표 3종, 제품 소개·가이드 캡처.
> **한계**: 로그인 계정이 없다. 아래는 **문서와 캡처에 적힌 것**이고, 확인 못 한 것은 그렇게 적었다.
> 【사실】= 문서에 적힌 것 / 【판단】= 우리 해석.

## 0. 한 장 요약

부기사의 상업용 매물관리 솔루션은 **왼쪽 탭 여섯**으로 갈린다.

| 탭 | 그들에게 있는 것 | 우리 상태 |
|---|---|---|
| 관리자 | 로그인·직원·종류·지도설정·**입금/급여**·작업이력·연장·**이관** | 팀 초대·제외까지. 급여·실적 없음 |
| 매물 관리 | 등록·목록·**관심매물**·**수정일 확인**·**담당자 만료**·검색필터·이관·사진첩 | 검색·건물상세·매물. 굵게 친 셋이 없다 |
| 고객 관리 | 등록·목록·**매칭 및 매물 공유**(72h 링크) | 매수자. 갈래 2 vs 그들 7 |
| 디자인 | 대표 디자인·스타일·컬러(사무소가 고른다) | 고정 — 우리는 이 길을 안 간다 |
| 마케팅 | 카카오공유·SEO·블로그·인스타·홍보문구·**프린트(IM 자료)** | 분석보고서·브리핑 |
| 기타 기능 | 데이터검색·부동산정보·일정·**임장**·문의·게시판·계산기·보안접속·제로콜 | 임장이 통째로 없다 |

**핵심 셋.**
1. **적정가·임대 추정·미래가치는 부기사에 없다.** 계산기는 사용자가 숫자를 넣어야 답이 나온다. 우리 차별점은 유효하다.
2. **그들의 AI 는 글쓰기 도우미와 외주 전화 응대뿐이다.** 간판인 「AI 중개사」는 본문이 비어 있고 메뉴가 숨겨져 있다. 우리 어시스턴트와는 층이 다르다.
3. **우리가 굳이 다르게 만들어 손해 보는 곳이 여섯 있다.** 낱말·임장·확인일·플래그·고객갈래·관심그룹이다. 다르게 할 이유가 없는데 다르다.

## 1. 화면 어법 — 사람들이 이미 익은 모양

### 1-1. 목록은 엑셀형 표다

【사실】 매물 목록은 짙은 남색 헤더의 조밀한 표다. 한 줄에 서는 것:

    체크박스 · 매물번호 · 공개/추천 · 분류 · 사진 · 건물명 · 주소 · 규모 ·
    면적(대지/건축/연) · 금액(매매가·평단가·수익률) · 용도 · 담당자 · 등록일 · 링크 · 마케팅

열 14~15개, 한 화면에 6~7줄. **한 칸 안에서 값이 여러 줄로 쌓인다**(매매가 230억 / 평단가 9,735만 / 수익률 3.38%).
【사실】 목록 스타일을 관리자가 둘 중 고른다.

【판단】 여기는 **우리가 다른 게 맞다.** 다만 「표로 보기」 토글 하나는 값싼 다리다. 그들도 스타일을 둘 준다.

### 1-2. 조작은 줄마다 글자 네모버튼 스무 개

【사실】 매물 한 줄에 붙는 버튼: 변경내역·링크·비밀·업무·고객·매칭·임장·주소복사·지도이동·면적토글·
확인일저장·확인일변경·매물프린트·매물상태변경·복사·갱신·인스타발송·블로그복사·홍보문구·매물공유·수정·삭제.
줄 오른쪽에 작은 pill 이 3열 × 5~7행으로 쌓인다.

【판단】 **이건 배우지 않는다.** 기능을 다 붙이려다 다다른 종착점이고, CLAUDE.md 가 금지하는 바로 그 모양이다.

### 1-3. 등록은 별도 전체 페이지, 부속은 모달

【사실】 `매매등록`/`임대등록` → 전용 페이지. 섹션 13개(기본·위치·금액·토지·건축물대장·고객·**업무일지**·
상세·사진·파일·**층별 임대차 현황**·템플릿·등기부등본). 저장은 상단 우측 하나. 1분마다 임시저장(옵션).
【사실】 모달: 건축물대장 선택, 매칭, 발송, 상태변경, 계산기. 관심매물 그룹만 **별도 팝업 창**.

【판단】 우리는 통합 모달 하나로 간다(0128 확정). 다만 **등록만은 전체 페이지가 맞을 수 있다** — 섹션 13개를 모달에 넣으면 스크롤 지옥이다.

### 1-4. 등록폼 안에서는 칩을 쓴다 — 여기가 중요하다

【사실】 라이브 캡처 확인:

| 칸 | 모양 |
|---|---|
| 진행상태 | **작업 / 준비 / 보류 / 완료** — 칩 4개, 선택된 것만 채움 |
| 대분류 | **통사옥 / 상가주택 / 기타** — 칩, 단일 |
| 소분류 | **실사용 / 투자용 / 신축용** — 칩, 중복 가능 |
| 라벨 | **대로변 / 신축 / 역세권** — 칩, 7자 이내, 색 지정 |
| 플래그 | **공개 · 추천 · 전속 · 급매** — 체크박스 |
| 담당자 | `<select>` |

【판단】 **부기사도 분류·상태는 칩이다.** 「중개인이 셀렉트에만 익어 있다」는 전제는 틀렸다.
우리 칩 어법(CLAUDE.md)은 낯선 게 아니라 **이미 익은 모양**이다. 자신 있게 가도 된다.

### 1-5. 색은 사무소가 고른다

【사실】 대분류·소분류·옵션·라벨·상태마다 **색을 지정**하고, 그 색이 지도 클러스터 색이 된다.
별도로 「수정일 확인 설정」에서 1~3개월·3~6개월·1년초과 구간에 색을 붙이면 방치된 매물 줄이 그 색으로 칠해진다.

【판단】 색 정책은 **우리가 옳다**(뜻 하나씩, 파랑+빨강). 테넌트마다 색이 다르면 화면이 사무소마다 딴판이 된다.
다만 **낱말은 늘릴 수 있어야 한다** — 사무소마다 「작업/준비」를 다르게 부른다.

### 1-6. 검색은 화면 위 두세 줄을 통째로 먹는 셀렉트 밭

【사실】 1줄에 정렬 탭 7개 + 보기 개수 + 검색칸 + 선택기능 + 등록버튼. 2~3줄에 셀렉트 15~20개.
관리자가 「검색 필터 설정」에서 순서 드래그·이름 변경·사용유무를 정한다(매매/임대/지도 각각).
【사실】 매물 검색 키워드에 **비밀메모**가 포함된다. 고객 검색은 이름·이메일·연락처·매물번호.

### 1-7. 지도

【사실】 배치 셋: 지도+우측 카드 리스트 / 지도+정보 패널(필지 클릭 시 실거래·건물정보) /
**필지 합산 모드**(여러 필지 선택 → 개수·면적합계·공시지가합계).
【사실】 지도는 카카오·네이버·구글 중 택1이고 **API 키를 고객사가 직접 발급해 붙인다.**
【사실】 **건물 노후도 탐색** — 지도 색으로 구분.

## 2. 흐름 — 매물 하나가 계약까지

【사실】 문서에 적힌 경로 열두 걸음.

| # | 화면 | 하는 일 |
|---|---|---|
| 1 | 매물 목록 → `매매등록` | 등록폼 열기 |
| 2 | 등록폼 13섹션 | 주소 → **건축물대장 모달에서 선택** → 면적·용도 자동. 고객·업무일지도 이 폼 안에서 |
| 3 | 목록 줄 `업무` | 업무일지 추가·조회 |
| 4 | 목록 줄 `매칭` | 이 매물에 맞는 고객 |
| 5 | 고객 줄 `자동매칭` | 반대 방향 → **1차/2차/3차/4차 담기** |
| 6 | 고객 줄 `대상물건` | 담은 매물, 순서 드래그 |
| 7 | `링크생성` | 목록형/지도형, **72시간 만료**, 중지/재개, 내역 |
| 8 | 목록 줄 `임장` | 그 주소로 임장 등록 |
| 9 | 일정 관리 | 달력 클릭 → 제목·공유권한·분류·일시 |
| 10 | 목록 줄 `매물상태변경` | 상태 + **매각일·매각금액** |
| 11 | 고객 줄 상태 셀렉트 | 진행→계약 인라인 |
| 12 | 입금/급여 → `실적등록` | 중개·컨설팅 수수료, 담당자 vs 물건담당자 |

【사실】 **「계약」이라는 화면이 없다.** 계약은 매물 상태·고객 상태·실적 등록 **셋으로 흩어진다.**
계약서·확인설명서 작성은 상업용 가이드에 없다(종합형에 「가계약」 메뉴만 따로 있다).

【판단】 **여기가 우리가 이긴 자리다.** 우리 계약 칸 하나가 「누구와·얼마에·언제」를 다 안고,
낱말이 한 파일에서만 나온다. 그들은 세 곳을 따로 고쳐야 하고 서로 안 묶인다.

### 2-1. 매칭

【사실】 고객 등록 시 조건: 선호 지역(시도·구군·동), 선호 역(호선·역), 희망 매입 가격대,
희망 보증금 가격대, 희망 대지면적. **고객 분류마다 입력폼이 다르다.**
【사실】 `자동매칭` = **조건 범위 일치 검색**이다. 점수·순위·유사도는 문서에 없다.
【사실】 1~4차 담기의 뜻은 문서에 정의가 없다(브리핑 회차로 보이나 **확인 못 함**).

### 2-2. 일정·임장

【사실】 일정 — 월 달력 / 주 리스트. 카테고리를 만들고 색을 준다. 실제 예: **미팅·통화·만기3개월전·잔금**.
「미팅 카테고리 사용」을 켜야 **시간 입력칸이 생긴다**(기본은 날짜만).
**매물·고객을 거는 칸이 문서에 없다.** 권한(누구에게 공유)만 있다.

【사실】 임장 — **독립 화면**. 지도 클릭 또는 주소 검색으로 등록. 팝업에 주소·카테고리·일자·메모.
실제 카테고리: **최우선임장 · 우선순위 높음 · 보통 · 낮음 · 임장 완료**.
**임장 로그** 페이지에 등록·수정·삭제 이력을 담당자·IP·시각까지 남긴다.
매물 줄의 `임장` 버튼이 그 주소로 임장 화면을 연다 — **매물↔임장은 주소로 이어진다.**

### 2-3. 업무일지

【사실】 매물 등록폼 안의 한 섹션. **종류 셀렉트**(기본 「미팅」, 종류는 관리자가 콤마로 나열) +
**파일 첨부**(「계약서나 매물 관련 자료」) + 내용 + `일지등록`.
【사실】 **담당자 만료 설정의 갱신 기준**을 「업무일지」 또는 「매물 수정일」 중 고른다 —
즉 업무일지가 **담당자 유효기간의 시계**다.
【사실】 상업용에는 업무일지 전용 목록이 없다(홈페이지·종합형에는 있다). 고객 쪽 업무일지는 문서에 없다.

## 3. 낱말 — 그들 말 그대로

| 축 | 부기사 | 빌탐정 |
|---|---|---|
| 매물 진행상태 | **작업 · 준비 · 보류 · 완료**(사용자가 추가·색 지정) | 사다리: 소유자·접촉·정보·계약·잔금·신고 |
| 합의 단계 | 없음 | 합의 전·합의중·계약예정·계약완료·중도금·거래종료 |
| 매물 대분류 | **통사옥 · 상가주택 · 기타** | — |
| 매물 소분류 | **실사용 · 투자용 · 신축용**(중복) | 활용유형(신축·리모델·수익·사옥) |

| 플래그 | **공개 · 추천 · 전속 · 급매** | — |
| 거래 종류 | **매매 / 임대**(등록 버튼부터 갈린다) | 매도 / 매수 |
| 고객 갈래 | **매수인·매도인·협력사·임대인·임차인·건물관리인·임대관리인**(7) | 매수자 / 매도인·소유자(2) |
| 고객 상태 | **진행·계약·보류·종료·해약** | 사다리 칸 |
| 고객 그 밖 | **유입경로·등급·고객그룹·고객구분(개인/법인)** | 매수 등급·유입경로 있음 |
| 일정 분류 | **미팅·통화·만기3개월전·잔금** | — |
| 임장 분류 | **최우선임장·우선순위 높음/보통/낮음·완료** | — |
| 기록 | **업무일지**(종류+내용+파일) | 메모창 |
| 고객 앞 가리기 | **보안접속** · 매물상세 **고객뷰 OFF** · 지도 **브리핑 모드** | 브리핑 |
| 수수료 | **실적**(중개/컨설팅), **물건수수료**, 담당자 vs **물건 담당자** | 중개보수 |
| 인쇄물 | **IM 자료 / 매물프린트** | 분석보고서 / 브리핑 |
| 매물 바구니 | **관심 매물 · 관심 그룹**(「50억대매물」) | — |
| 갱신 | **확인일 저장 / 확인일 변경 / 갱신** | — |

【판단】 벽이 될 낱말 셋: **업무일지 · 임장 · 전속/급매/확인일**.
사용자가 이미 아는 말을 우리가 바꿔 부르면 그것만으로 벽이다.

## 4. 그들이 나은 곳 다섯

다르게 할 이유가 없는데 다른 것들이다. 위에서부터 싸고 효과가 크다.

| 4 | **전속 · 급매 · 추천 · 공개 플래그** | 없음 | 매물에 칩 넷. 없으면 메모에 손으로 적게 된다 | 작다 |
| 5 | **고객 갈래 7**(협력사·건물관리인 포함) | 2 | **협력사(공동중개)** 와 **건물관리인**을 먼저 넣는다. 상업용은 공동중개 비중이 크고 관리인은 정보 통로다 | 중간 |

### 배우지 말 것

- 줄마다 네모버튼 스무 개, 상단 셀렉트 스무 개. 기능을 다 붙이려다 다다른 종착점이다.

- 디자인·스타일·컬러 설정. 그들은 홈페이지 제작이 본업이라 필요하고, 우리는 아니다.
