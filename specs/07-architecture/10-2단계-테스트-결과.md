## 2. 대표 케이스 · 카카오맵으로 층별 임대 채우기

대표의 출발점: 「카카오맵을 검색엔진으로 들어가서 업체 주소를 보면 층 정보가 나오는 것들이 있으니까
이걸 활용해서 층별임대정보를 채울 수 있겠는데?」

### 무슨 일이 있었나 (#15-5 → 15-9)

```
"성수동 78번지 ··· 카카오맵 기반으로 채워줘"
   → suggest("성수동 78")  후보 0
   → "후보가 없다. 1가인지 2가인지 알려주시면"  ← 문장 되물음
   → "카카오맵 정보를 옮겨 적어 드릴 수 없다. 사실 확인 없이 지어내는 셈"

"삼성동 78임"
   → suggest("삼성동 78")  후보 6
   → ask 칩 여섯  ← 됨

"삼성동 78번지"
   → suggest → /buildings/1024123619/floor-rents  items: []
   → "팀이 등록한 층별 임대 없음. 카카오맵 등 외부 지도 서비스의 정보를 가져와 채워드릴 수 없다"
   → "어느 걸 보시겠어요"  ← 꼬리말
```

### 왜 못 했나 · 세 겹

| | 막은 것 | 어디서 |
|---|---|---|
| ① | **쓰기가 없다.** `floor-rents` 에 넣는 건 쓰기 API 고 `x-ai="write"` 는 6단계다 | 정본 §24 |
| ② | **카카오 업체 길(`places`)을 일부러 닫았다.** 기존 결정 「카카오 로컬 데이터는 DB 에 저장하지 않는다」 때문이다. 모델이 읽어 답에 실으면 `ai_message` 에 글자로 저장된다 | `api.py` 열기 목록 · 커밋 a37da7f |
| ③ | 웹 검색은 「우리 자료에 없는 것에만」이라 카카오맵 페이지를 찾으러 안 갔다. 갔더라도 ②와 같은 문제 | `prompt.TOOLS_HOW` |

모델이 말한 「팀이 직접 확인해 적는 값이라 못 옮긴다」는 **데이터 모양에서 스스로 추론한 정책**이다.
결과적으로 우리 규칙과 맞았지만, 우리가 지시문에 적은 말은 아니다. 다음에 다르게 말할 수 있다.

### 이 아이디어를 살리려면 정할 것

1. **카카오 저장 정책과 AI 흐름이 부딪친다.** 승인 어법(§12-2)대로 「AI 가 층별 임대 모달을 채워 열고 사람이 저장」하면
   저장하는 주체는 사람이다. 그러면 「팀이 적은 값」인가 「카카오 데이터 저장」인가. 그리고 채우기 전에 모델이 읽은
   카카오 결과가 답(`ai_message`)에 남는 문제는 그대로다.
2. 순서상 **6단계(쓰기) 전에는 어차피 안 된다.** 읽기만으로는 「채워줘」가 성립하지 않는다.
3. 이미 있는 길이 있다. `/tenants` 가 인허가(LOCALDATA, 층 80%)·소상공인(층 68%) 원장으로 층별 업체를 붙인다.
   카카오는 **그 원장에 없는 것을 보태는 자리**다. 「카카오로 채운다」보다 「원장으로 채우고 빈 곳만 카카오」가 맞다.

## 6. 기록 양식

이어서 테스트하실 때 아래 줄을 §1 표에 보태면 된다. 대화 번호는 사이드바 제목을 누르면 주소에 안 뜨니
`select id, title from app.ai_chat order by id desc limit 5` 로 본다.

```
| # | 질문 | 도구 (바퀴) | 토큰 | 결과 한 줄 | ○ △ ✗ | 원인 · 비고 |
```

판정은 셋이다. **✗** 는 차단 항목(오염 · 지어내기 · 권한 · 바퀴 소진)을 어긴 것, **△** 는 답은 됐는데 어법·바퀴·되물음이 어긋난 것, **○** 는 그대로 고객 앞에 내도 되는 것.
