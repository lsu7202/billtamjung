### 1-4. DB (마이그레이션 0242)

**`master.trade`** · 거래 한 건 = 원천 한 줄. 매칭과 떼어 둔다.

| 칸 | 형 | 원천 |
|---|---|---|
| id | bigserial PK | |
| kind | text | 파일 갈래(단독다가구 · 상업업무용 · 아파트 · 연립다세대 · 오피스텔 · 토지 · 분양입주권 · 공장창고) |
| bjd_code | text | 시군구 이름 → 법정동코드 |

| road_name | text | 도로명 |

없는 칸은 null. 갈래마다 원천 칸 이름이 달라 빌더가 위 이름으로 맞춘다(값은 바꾸지 않는다).

**거래의 열쇠는 거래 ID 다**(10-08 대표). 주소는 열쇠가 아니라 **붙이기 위한 재료**다. 못 붙인 거래도 버리지 않는다 — 법정동까지만 채우고 지번은 비워 둔다. 모델은 「어느 지번인지는 모르지만 이 동에서 이런 거래가 있었다」로 쓸 수 있다.

**`master.trade_match`** · 거래 → 우리 지번(붙은 것만 한 줄).

| 칸 | 형 | 뜻 |
|---|---|---|
| trade_id | bigint PK → trade | |
| pnu | text | 붙은 지번 |
| method | text | `번지그대로`(집합) · `전부일치`(통매) |

**붙이는 규칙 · 방식마다 다르다. 하나라도 안 맞으면 붙이지 않는다**(10-08 대표 「연면적 · 건축년도 · 대지면적이 안 맞는 건 매칭시키면 안 된다」 · 부동산플래닛 · 나라데이터에도 그런 거래는 그 지번에 안 뜬다).

| 방식 | 규칙 |
|---|---|
| 집합(호실) | 번지가 가려지지 않는다. 법정동 + 본번 · 부번(부번 없으면 0)으로 지번 하나 |
| 통매(상업업무용 일반 · 단독다가구) | 법정동 · 번지 마스크(산 · 자릿수 · 앞자리) · 도로명이 맞는 지번 중, 대지면적(필지 면적 또는 그 동이 걸친 필지 합 ±2%) **그리고** 연면적(한 동 ±3%, 또는 그 지번 모든 동의 합 ±3%) **그리고** 건축년도(한 동으로 맞았으면 그 동 ±1, 합으로 맞았으면 지번의 어느 동이든 ±1 · 원천에 없으면 빼고) 가 다 맞는 지번이 **하나뿐**일 때만 |
| 지분 | **붙이지 않는다**(10-08 대표). 신고 면적이 지분 몫이라 전체 면적과 맞는 것이 5.6% · 비율 대조는 「여럿」이 더 많아 못 믿는다. 거래 표에 법정동까지만 남는다 |
| 해제 | 방식 규칙은 같다. 칸 `canceled_on` 으로 구분 · 시세에서는 빼고 「매각 의사가 있었던 땅」 신호로 남긴다 |

- 가려진 번지(`3**`)는 원천 표(`trade.jibun_raw`)에 두고 빌드에서 후보를 좁히는 데 쓴다. **모델 뷰(층 2 실거래)에는 칸을 열지 않는다**(10-08 대표 「모델이 헷갈린다」). 모델이 보는 위치는 붙은 지번(pnu) 또는 법정동뿐이다.
- 대장 대지면적은 대조에 쓰지 않는다 — 실거래의 대지면적은 필지(땅) 면적이다(10-07 측정: 지금 붙은 것의 47% 가 빌더가 필지 면적으로 채운 값과 맞아 붙었다).
- 화면 · 모델이 지번으로 실거래를 찾을 때는 `trade_match` 로, 동 전체를 볼 때는 `trade.bjd_code` 로.
- `master.sales_history` 와 `sales_agg` MV 는 **지운다.** 읽는 곳(1-1 목록)을 `trade` + `trade_match` 로 옮긴다. 통건물 실거래 = `deal_kind IS DISTINCT FROM '집합' AND canceled_on IS NULL AND kind IN (…통건물 갈래)`.
- `buildings.last_sale_*` 되붙임(`fill_sale_latest.py`)도 같은 조건으로.

### 1-5. API (경로는 그대로 · 원천만 바꿈 · 경로는 단계 3 에서 지번으로)
- **실거래 유형과 매물유형은 다른 칸이다(10-08 결정 · 0246~0249).** 실거래 유형은 신고 서식이 정한 갈래, 매물유형은 매물을 올린 사람이 고른 갈래. 같은 건물이라도 다르다(청담동 16: 네이버 「빌딩」 · 대장 단독주택 · 실거래 단독다가구). 칸 · 사전이 따로이고 서로를 읽지 않는다. 대장으로 센 유형(`building_derived.use_kind`)은 지웠다(0247).
- 실거래 유형 `master.trade.trade_type`(생성 칸, 사전 `ref.enums trade_type`) — 원천 칸만으로 정한다. 대장으로 고쳐 쓰지 않는다(신고 당시 사실이 지워진다).

  | 원천 파일 | 유형 · 건축물주용도 | trade_type |
  |---|---|---|
  | 상업업무용 | 용도 숙박(일반 · 집합) | 숙박시설 |
  | 상업업무용 | 집합(숙박 제외) | 상가/사무실 |
  | 상업업무용 | 일반 · 용도 기타 · 교육연구 | 기타건물 |
  | 상업업무용 | 일반 · 그 밖 | 상업용건물 |
  | 단독다가구 · 연립다세대 · 오피스텔 · 토지 · 공장창고 | | 단독/다가구 · 연립/다세대 · 오피스텔 · 토지 · 공장/창고 |
  | 아파트 · 분양입주권 | | 비움(거래 대상 아님) |
- `master.trade_parcel`(MV, 0249) — 지번에 붙은 거래 전부(통매 · 호실 · 토지), 해제 · 0원 · 비운 유형 제외. `use_label` = 원천 건축물주용도, 없으면 실거래 유형. `load_trades.py` 가 새로 고친다. 보통 뷰로 두면 검색 실거래 보기 플래너가 무너졌다(강남 한 화면 30초 → MV 0.5초).
- `GET /buildings/{pk}/sales-history` · 상세 `sales_history`: `trade_parcel`. 응답 `use` · `trade_type` · `deal_kind` · `floor` · `excl_area`. 상세 실거래 표에 「용도」 칸(원천 용도 · 층). 직전 대비는 같은 실거래 유형끼리.
- `/search` 실거래 보기: `filters.trade_types` 로 LATERAL 안에서 거른다(핀 값 = 고른 유형의 최근 거래). 핀 머리 칸 = `trade_use`(원천 용도, 없으면 실거래 유형). 매물유형(`kinds`)은 안 본다. 가격지표 설정의 실거래 줄 = 실거래유형 아홉 칸.
- `POST /market/nearby` · `GET /nearby-sales/{pk}`: 단가 비교 사례라 통매(`trade_whole`)만. 응답에 `trade_type` · `trade_use`.
- 매물유형 `ref.enums building_major` 아홉 칸(상업용건물 · 상가/사무실 · 단독/다가구 · 연립/다세대 · 오피스텔 · 토지 · 공장/창고 · 숙박시설 · 기타건물). 매물유형 = 팀이 고른 대분류, 없으면 네이버 유형(`app.naver_major(listing_crawl.ad_use_type)`, 대응은 사전 `meta.naver` 한 곳), 둘 다 없으면 비움. 대장으로 채우지 않는다(광고 초안 포함).
  네이버 빌딩 · 상가건물 · 상가주택 → 상업용건물 · 숙박 → 숙박시설 · 공장창고 → 공장/창고 · 빌라 · 연립 · 다세대 · 도시형생활주택 → 연립/다세대 · 단독/다가구 · 전원주택 · 한옥주택 → 단독/다가구 · 오피스텔 · 토지.
- 매매시세 핀(`/market/pins?kind=sale`)은 지웠다 — 화면에서 부르는 곳이 없었다.

- 매물 표 · 매물 모달 · `?listing=` · 일정 `onSeller` → listing_id.
- 나대지 갈림(`!vacant` · `pk.startsWith("P")` · `'P'+pnu`)을 지운다. 나대지는 동이 없는 지번일 뿐이다.
- 모델 자료 · 렌더(`render/` · `ai/`)가 새로 만드는 링크는 `/parcels/{pnu}`.
- 대지면적(대장)이 없는 동은 **빈칸 그대로**(10-08 대표). 땅 크기는 토지면적(지적 · 늘 채워짐)이 따로 보여 준다. 둘을 한 칸에 섞지 않는다.
- 지번 페이지에 대장 딸림 정보를 연다(10-07 대표): 에너지(`building_energy`) · 정화조(`building_septic`) · 지역지구구역(`building_zone`). 층 1 뷰에도 같은 셋. 단지(`building_complex`) · 사라진 건물(`building_closed`)은 **층 1 · 모델 뷰에만 열고 화면은 대기**(10-08 대표). 표는 지우지 않는다.

### 3-7. 검증
네 경우 × 화면(탐색 지도 · 사이드 판 · 지번 페이지 · 매물 표 · 매물 모달 · 광고 · 매수자 담기 · 모델 지도)을 눌러 스크린샷:
1. 한 동 지번
2. 동이 둘인 지번의 둘째 동(지도 클릭 · 동 칩 둘 다)
3. 나대지
4. 지번 둘짜리 매물

`qa/screen` 에 넷을 경로로 넣는다. QA mirror · data · units · ai.
