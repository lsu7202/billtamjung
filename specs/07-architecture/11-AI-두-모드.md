> 2026-10-04 대표 결정. 정본 [10-AI-어시스턴트](10-AI-어시스턴트.md)에 모드를 더한다.

## 2. 구조로 막는 다섯 자리

### 2-1. 모드는 토큰이 정한다
- 모드 = 토큰의 계정 종류(`kind`). 요청 몸통 · 쿼리에 모드 칸을 두지 않는다. 바꿀 길이 없다.
- 대화는 만들 때 모드가 박힌다(`ai_chat.mode`). 다른 모드 계정이 그 대화에 쓰면 409.

### 2-2. 도구 목록이 모드마다 따로다
- `REGISTRY` 하나를 `BROKER_TOOLS` · `CUSTOMER_TOOLS` 둘로 가른다(§4).
- 모델에게 선언하는 것도, 모델이 부른 이름을 핸들러로 찾는 것도 **그 모드의 목록 안에서만** 한다.
  목록에 없는 이름을 부르면 「없는 도구」 오류가 되돌아간다. 고객 모델은 `make`를 선언받지 못하고, 불러도 안 돈다.

### 2-3. 칸은 허용 목록으로만 나간다
- 모델에게 나가는 칸은 모드별 **허용 목록**(`LENS[mode]`)을 지나야 한다. 거부 목록이 아니다.
  새 칸이 생기면 기본이 「안 보임」이다. 넣으려면 허용 목록에 한 줄을 적어야 한다.
- 이 거름은 나가는 문(`agent.Exec`) 한 곳에 둔다. 도구가 무엇을 돌려주든 마지막에 지난다.
- 조건(필터) 스키마도 같은 목록에서 만든다. 고객 스키마엔 `급함`·`소유자` 같은 이름이 아예 없다.
  핸들러는 모드별 `Filters` 모델(`extra="forbid"`)로 다시 검사한다. 스키마를 우회한 이름은 422.
- SQL도 겹으로 막힌다. 고객 토큰은 `team_id`가 없어서 팀 조인이 빈다(이미 그렇다).
  네이버 시세 · 임대내역 묶음 핸들러는 `is_broker(user)`가 아니면 빈 값을 돌려준다.

### 2-4. 모델은 쓰지 못한다. 쓰기는 사람이 누른다
- 구해요 · 문의는 바깥으로 나가는 글이다. 모델 도구는 **초안 줄만** 만든다(`ai_action`, 상태 `draft`).
- 답에 확인 카드 조각(`t: "confirm"`, `action_id`)이 실린다. 화면이 카드를 그린다.
- 실제 등록은 `POST /ai/actions/{id}/confirm` 하나뿐이다. 이 라우트는 **사람의 화면만** 부른다.
  모델은 HTTP를 모른다(도구는 같은 프로세스 함수다). 모델이 확인할 길이 구조적으로 없다.
- 확인은 기존 도메인 함수(`seeks.add_seek` · `inquiries.create`)를 그대로 부른다. 규칙(한 건물 하나 · 200자 · 30일 · 동의)이 한 곳에 있다.
- 초안은 24시간 뒤 `expired`. 같은 초안을 두 번 확인할 수 없다(상태 전이 `draft → done` 한 번).

### 2-5. 내 투자는 장부에서 나온다. 모델은 근거를 대야 적힌다
- 내 투자 칸마다 **사실 장부**(`customer_profile_fact`)에 한 줄씩 쌓는다. 현재 값 = 칸마다 가장 최근 줄.
  `customer_profile`은 그 결과를 같은 트랜잭션에서 다시 적어 두는 사본이다(읽는 곳을 안 바꾸려고).
  프로필 + 커밋 장부 원칙([프로필-커밋](../04-data/프로필-커밋.md)) 그대로다.
- 고객이 손으로 고치면 `source='self'` 줄, 대화에서 읽으면 `source='chat'` 줄. **최근 줄이 이긴다.**
  손으로 30억을 적고 나중에 대화에서 「50억까지 봐요」라고 하면 50억이 된다.
- 읽는 일은 대화 모델이 아니라 **따로 도는 추출기**가 한다(§5). 추출기는:
  - **고객이 친 글만** 받는다. 모델 답은 안 넣는다. 모델이 권한 값이 고객 값으로 둔갑하지 못한다.
  - 함수 호출이 **강제**된다(도구 하나, `tool_choice` 고정). 스키마 밖 칸 · 값은 디코딩 단계에서 못 나온다.
  - 칸마다 `근거`(고객 글의 원문 구절)를 내야 한다. 서버가 그 구절이 그 범위의 고객 글 안에 **글자 그대로** 있는지 본다. 없으면 버린다.
  - 값은 pydantic으로 다시 검사한다(갈래 · 범위). 틀리면 그 칸만 버린다. 조용한 실패가 틀린 해석보다 낫다.
  - 말 안 한 칸은 스키마상 필수가 아니다. 안 내면 아무것도 안 적힌다.

## 3. 로그인 막기
- `/ai/*`는 전부 `any_user`(토큰 필수). 손님은 401이다.
- 화면: 손님 레일에서 「빌탐정」을 누르면 `/login?next=/assistant`. 라우트 `/assistant`도 손님이면 같은 곳으로 보낸다.
- 첫 화면은 그대로다. 중개사 = `/assistant`, 고객 = `/search`.

## 4. 도구

| 이름 | 하는 일 | 중개사 | 고객 | 쓰기 |
|---|---|---|---|---|
| `search` | 검색. 묶음 = 모드별(§1) | ✓ | ✓ | |
| `building` | 건물 한 채 + 묶음(`함께`) | ✓ | ✓(공개 묶음만) | |
| `invest` · `develop` | 투자 · 개발 셈 | ✓ | ✓ | |
| `make` · `fix` | 자료(아티팩트) | ✓ | | 자기 자료 |
| `ask` | 되묻기 | ✓ | ✓ | |
| `seek_draft` | 구해요 초안(건물 1~5 · 한마디) | | ✓ | 초안만 |
| `inquiry_draft` | 문의 초안(광고 하나 · 유형 · 내용) | | ✓ | 초안만 |

`building`의 `함께` 묶음도 모드별 허용 목록이다. 고객: 층별 · 필지 · 주변실거래 · 주변매각 · 주변동향 · 임대추이 · 입주이력 · 상권구성 · 시간대별유동인구 · 버스정류장 · 지하철역 · 공시지가추이 · 실거래이력 · **광고**. 중개사는 여기에 임대내역 · **시세**를 더한다.

### 검색 응답 모양
```
{ "단위": "...",
  "내매물": [...],          // 중개사만. 매각됨(보류 사유) 은 빠진다
  "광고":   [ {건물번호, 주소, 추정가, …, "광고": {"매매가", "중개사", "사무소", "올린날", "관심"}} ],
  "일반":   [...] }
```
광고 · 일반은 같은 칸(허용 목록)을 쓰고, 광고 줄에만 `광고` 묶음이 붙는다. 광고 매매가는 「매매가」가 아니라 `광고.매매가`다. 우리가 적은 매매가와 이름이 갈린다.

## 5. 내 투자 추출기

**언제:** 고객 대화의 답이 끝난 뒤(`chat_send` 마무리) 백그라운드로 한 번. 그 대화에서 `extracted_seq` 이후의 **고객 글**만 넣는다. 다 돌면 `extracted_seq`를 올린다. 같은 글을 두 번 읽지 않는다.

**도구 스키마(강제 호출, 이름 `내투자`):**
```json
{ "type": "object", "properties": {
  "희망매매가_최소": {"type":"object","properties":{"억":{"type":"number","minimum":0},"근거":{"type":"string"}},"required":["억","근거"]},
  "희망매매가_최대": { 같은 꼴 },
  "희망매매가_상관없음": {"type":"object","properties":{"근거":{"type":"string"}},"required":["근거"]},
  "시드":     { "억" + "근거" },
  "목표":     {"type":"object","properties":{"값":{"type":"array","items":{"enum":["시세차익","수익률","실사용"]}},"근거":{}},"required":["값","근거"]},
  "원하는지역": { "값": 25개 구 enum 배열, "근거" },
  "매수시기": { "값": enum ["3개월 안","6개월 안","1년 안","미정"], "근거" },
  "건축의사": { "값": enum ["있음","없음","모름"], "근거" },
  "개인법인": { "값": enum ["개인","법인"], "근거" },
  "매입경험": { "값": enum ["처음","보유 경험"], "근거" },
  "찾는조건": { "조건": search 의 고객용 조건 스키마 그대로, "근거" }
}}
```
필수 칸은 없다. 갈래 값은 화면 칩과 **같은 목록**에서 만든다(`CustomerFields`의 GOALS · TIMING 등을 서버 상수로 옮겨 한 곳에 둔다).

**적는 규칙(코드):**
1. `근거`가 범위 안 고객 글에 글자 그대로 없으면 그 칸을 버린다.
2. 값을 pydantic으로 검사한다. 실패한 칸만 버린다.
3. 남은 칸마다 `customer_profile_fact`에 `source='chat'` 줄을 넣고, `customer_profile`의 그 칸을 갈아 끼운다(한 트랜잭션).
4. `찾는조건`은 `saved_searches`에 `source='chat'`인 줄 **하나**를 고쳐 쓴다(없으면 만든다). 고객이 직접 저장한 조건은 안 건드린다.
5. 희망매매가 최소 · 최대를 적으면 상관없음은 지운다. 상관없음을 적으면 최소 · 최대를 지운다(화면 규칙과 같다).

**보이기:** 내 투자 상자는 지금처럼 값을 보인다. 대화에서 읽은 칸엔 칸 아래 작은 회색 「대화」 표시(출처)를 단다. 누르면 근거 구절과 날짜가 보인다. 손으로 고치면 그 표시는 사라진다(최근 줄이 `self`).

## 6. API

### 바뀌는 것
| 메서드 · 경로 | 인증 | 바뀜 |
|---|---|---|
| `GET /ai/chats` · `POST /ai/chats` · `GET/PATCH/DELETE /ai/chats/{id}` | `any_user` | `current_user` → `any_user`. 만들 때 `mode` = 토큰 kind |
| `POST /ai/chats/{id}/messages` (SSE) | `any_user` | 모드의 도구 · 허용 목록으로 돈다. 대화 모드 ≠ 토큰 kind 면 409. 고객이면 끝에 추출기를 건다 |
| `GET /ai/tools` | `any_user` | 내 모드의 도구 스키마를 돌려준다(점검용) |
| `GET /customer/profile` | `any_user`(고객) | 응답에 `src: {칸: {source, at, quote}}` 를 더한다 |
| `PUT /customer/profile` | `any_user`(고객) | 바뀐 칸마다 `source='self'` 사실 줄을 쌓는다. 값 저장은 장부 경유 |

### 새것
| 메서드 · 경로 | 인증 | 하는 일 |
|---|---|---|
| `GET /ai/actions?chat_id=` | `any_user` | 그 대화의 초안들(카드 다시 그리기) |
| `POST /ai/actions/{id}/confirm` | `any_user`, 본인 것만 | 초안 실행. 구해요: `{note?}` 고쳐 보낼 수 있다. 문의: `{name, phone, consent}` 필수. 응답 `{ok, result_id}` |
| `POST /ai/actions/{id}/dismiss` | `any_user`, 본인 것만 | 초안 버림 |
| `GET /customer/profile/facts?field=` | `any_user`(고객) | 그 칸의 이력(근거 · 날짜 · 출처) |

### 확인 카드 조각
```json
{ "t": "confirm", "action_id": 31, "kind": "seek",
  "items": [{"건물번호": "...", "주소": "...", "이미남김": false}],
  "note": "성수동 30억대 꼬마빌딩 찾습니다" }
```
문의는 `kind: "inquiry"`, `ad_id`, `inquiry_kind`, `body`. 이름 · 전화는 카드에서 고객이 적는다(계정 값으로 미리 채움). 모델은 전화를 모른다.

## 7. 스키마(마이그레이션 0222 안)

```sql
-- 대화 모드 · 추출 위치
ALTER TABLE app.ai_chat
  ADD COLUMN mode text NOT NULL DEFAULT 'broker' CHECK (mode IN ('broker','customer')),
  ADD COLUMN extracted_seq int NOT NULL DEFAULT 0;

-- 모델이 만든 초안. 확인은 사람만
CREATE TABLE app.ai_action (
  id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  chat_id     bigint NOT NULL REFERENCES app.ai_chat(id) ON DELETE CASCADE,
  account_id  bigint NOT NULL REFERENCES app.accounts(id),
  kind        text   NOT NULL CHECK (kind IN ('seek','inquiry')),
  payload     jsonb  NOT NULL,
  status      text   NOT NULL DEFAULT 'draft' CHECK (status IN ('draft','done','dismissed','expired')),
  result_ids  bigint[],                 -- 만들어진 seeks.id / inquiries.id
  created_at  timestamptz NOT NULL DEFAULT now(),
  decided_at  timestamptz,
  expires_at  timestamptz NOT NULL DEFAULT now() + interval '24 hours'
);
CREATE INDEX ON app.ai_action(chat_id);

-- 내 투자 사실 장부. 현재 값 = 칸마다 최근 줄
CREATE TABLE app.customer_profile_fact (
  id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  account_id  bigint NOT NULL REFERENCES app.accounts(id),
  field       text   NOT NULL CHECK (field IN ('budget_min','budget_max','budget_any','equity_won','goal',
                     'regions','timing','build_intent','is_corp','experience','note')),
  value       jsonb,                    -- null = 지움
  source      text   NOT NULL CHECK (source IN ('self','chat')),
  chat_id     bigint REFERENCES app.ai_chat(id) ON DELETE SET NULL,
  quote       text,                     -- chat 일 때 근거 구절(고객 글 원문)
  created_at  timestamptz NOT NULL DEFAULT now(),
  CHECK (source = 'self' OR (chat_id IS NOT NULL AND quote IS NOT NULL))
);
CREATE INDEX ON app.customer_profile_fact(account_id, field, created_at DESC);

-- 대화에서 읽은 찾는 조건(고객당 하나)
ALTER TABLE app.saved_searches
  ADD COLUMN source text NOT NULL DEFAULT 'self' CHECK (source IN ('self','chat')),
  ADD COLUMN chat_id bigint REFERENCES app.ai_chat(id) ON DELETE SET NULL;
CREATE UNIQUE INDEX saved_searches_one_chat ON app.saved_searches(account_id) WHERE source = 'chat' AND closed_at IS NULL;
```

기존 `customer_profile` 값은 마이그레이션에서 `source='self'` 줄로 한 번 옮겨 장부를 시작한다.

## 9. 검증(구조가 막는지 보는 회귀)
- 고객 토큰으로 `make` 를 부르는 가짜 모델 응답 → 「없는 도구」.
- 고객 모드 검색 결과 JSON 에 허용 목록 밖 키가 하나도 없다(전 칸 훑기).
- 고객 조건에 `급함` → 422.
- `seek_draft` 뒤 `seeks` 줄 수가 그대로다. `confirm` 뒤에만 는다.
- 추출기에 근거가 고객 글에 없는 값을 넣은 가짜 응답 → 장부 줄 0.
- 모델 답에만 나온 「40억」 → 장부 줄 0(고객 글만 넣으므로).
- 손님 토큰 없이 `/ai/chats` → 401.

## 10. 열린 것
- 중개사 모드의 조회 보강(상태 · 전속 · 확인일 · 매물 유형 · 등급 등 조건, 시세 묶음)은 10-04 조회 점검 결과대로 같은 `LENS` 위에서 한다.
- 매물관리 · 내 매물 업로드 스킬은 이 구조 위에 중개사 도구로 더한다. 쓰기는 2-4와 같은 초안 → 확인 방식을 쓴다.
