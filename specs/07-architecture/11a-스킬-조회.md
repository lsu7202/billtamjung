# 11a · 읽기 API(모델 스킬)

> 2026-10-04 **승인**(§5 넷 포함). [11-AI-두-모드](11-AI-두-모드.md)의 읽기 쪽.
> **원칙 넷**
> 1. 읽기는 **대상마다 하나**다. 대상 안의 모든 읽기(찾기 · 한 건 · 묶음)는 그 하나로 한다. 대상끼리는 번호로 잇는다.
> 2. 모델 읽기는 **화면 API와 같은 함수**를 부른다. 중개사 = 매물 탐색 · 매물관리 표 · 고객관리, 고객 = 매물 찾기 · 구해요. 모델 전용 검색을 따로 두지 않는다.
> 3. 공개 값과 팀 값을 한 읽기에서 같이 건다. **팀 값은 토큰의 팀 · 내 매물 줄에만** 걸리고 보인다.
> 4. 응답은 **물어본 칸만** 싣는다. 내 매물이라고 팀 값을 통째로 붙이지 않는다.

## 0. 읽기 도구

| 도구 | 대상 | 중개사 | 고객 | 부르는 화면 함수 |
|---|---|---|---|---|
| **건물 조회** `buildings` | 건물 · 나대지 · 내 매물 | ✓ | ✓ | `search.search`(탭 explore · ad · all) · `buildings.get_building` · 묶음 함수들 |
| **고객 조회** `customers` | 우리 고객 · 문의 | ✓ | | `buyers.list_buyers` · 고객 판 · `inquiries` |
| **내 정보** `me` | 나(고객) | | ✓ | `customer.profile` · `saved_searches`(내 것) · `seeks`(내 것) · `inquiries/mine` |

투자 · 개발 셈(`invest` · `develop`)은 읽기가 아니라 계산이라 따로 있다(그대로). 일정은 스킬에서 뺐다(0222).

## 1. 건물 조회 `buildings`

### 1-1. 입력
```jsonc
{
  "조건": [ { "지역": "종로구", "대지면적": {"이상": 150}, "명도": {"값": ["쉬움"]} } ],  // 목록 = 「또는」 갈래, 갈래 안은 「그리고」
  "출처": ["내매물", "빌탐정매물", "네이버매물", "일반"],   // 안 주면 모드 기본(아래)
  "고객": 12,            // 중개사만. 그 고객에게 붙은 조건을 서버가 펼쳐 「또는」 갈래로 더한다
  "저장조건": 31,         // 그 저장한 조건을 서버가 펼친다. 고객 모드는 내 것만
  "보기": ["연면적", "명도", "층별"],   // 줄에 실을 칸 · 묶음. 조건에 건 이름은 저절로 실린다
  "정렬": "대지면적", "차순": "내림차순"
}
```
- `조건`의 이름 사전은 하나다(§1-4 표). 걸면 거르고, 이름만 대면(`{}`) 보인다. 지금 어법 그대로다.
- `고객` · `저장조건`은 **서버가 펼친다.** 모델이 고객 조건을 옮겨 적다 틀릴 자리가 없다.
- 한 채만 보려면 `{"건물번호": "…"}` 또는 `{"주소": "누상동 94"}`를 건다. 따로 「한 채 보기」 도구가 없다.

### 1-2. 출처(묶음) = 화면의 출처
| 출처 | 뜻 | 화면 | 중개사 | 고객 |
|---|---|---|---|---|
| 내매물 | 우리 팀 매물. 보류 사유 「매각됨」은 뺀다 | 매물 탐색 「내 매물」 | 기본 ✓ | ✗ |
| 빌탐정매물 | 노출 중 광고가 있는 건물(내 매물 제외) | 탐색 「빌탐정 매물」 · 매물 찾기 | 기본 ✓ | 기본 ✓ |
| 네이버매물 | 최근 수집일 네이버 매매(통매) | 탐색 「네이버 매물」 | 기본 ✓ | ✗ |
| 일반 | 위 셋에 없는 건물 · 나대지 | 탐색 지도 · 구해요 | 기본 ✓ | 기본 ✓ |

한 건물은 한 출처에만 선다(위에서 아래 순서). 스키마 자체가 모드별로 다르다. 고객 스키마의 `출처` enum엔 빌탐정매물 · 일반 둘뿐이다.

### 1-3. 출력
```jsonc
{ "단위": "면적 ㎡ · 금액 원 · …",
  "내매물":     { "전체": 4,   "보여준수": 4,  "목록": [ {줄}, … ] },
  "빌탐정매물": { "전체": 37,  "보여준수": 20, "목록": [ … ] },
  "네이버매물": { … },
  "일반":       { "전체": 2311, "보여준수": 20, "목록": [ … ] } }
```
**줄의 뼈대(늘 실림):** `건물번호 · 주소 · 대표가격 · 대표가격출처`
| 출처 | 대표가격 | 대표가격출처 |
|---|---|---|
| 내매물 | 우리 매매가(없으면 비움) | 매매가 |
| 빌탐정매물 | 광고 매매가(여럿이면 최소, 비공개면 비움) | 광고 |
| 네이버매물 | 최근 수집 매매가 | 네이버 |
| 일반 | 추정가 | 추정 |

그 밖의 칸은 `보기`나 `조건`에 이름이 있을 때만 실린다. 팀 칸 이름을 대도 **내매물 줄에만** 실린다.

## 3. 내 정보 `me` (고객만)
입력 없음(본인). 출력: `내투자`(희망매매가 · 시드 · 목표 · 지역 · 시기 · 건축의사 · 개인법인 · 매입경험) · `찾는조건`(내 저장 조건, 건물 조회 `저장조건`에 그대로) · `관심매물` · `구해요`(건물 · 상태 · 제안 수) · `보낸문의`(매물 · 상태).
상담할 때 이미 아는 것을 다시 묻지 않으려고 둔다.

## 4. 구조로 지키는 것
- **스키마가 모드마다 다르다.** 고객 스키마엔 팀 · 네이버 이름, `고객` 손잡이, 내매물 · 네이버매물 출처가 없다. `customers` 도구는 고객에게 선언되지 않는다.
- **핸들러가 다시 막는다.** 모드별 조건 모델(`extra="forbid"`)로 검사한다 → 422. 고객 토큰엔 팀이 없어 팀 조인이 빈다. 네이버 · 임대내역 · 짝 묶음은 `is_broker`가 아니면 빈 값.
- **전화는 어디에도 없다.** 사전에 이름이 없어 요청할 길이 없다(`전화있음`만).
- **팀 칸은 내매물 줄에만.** 출력 조립에서 출처가 내매물이 아닌 줄은 팀 칸 키를 아예 안 만든다.

## 5. 결정(10-04 승인)
1. 고객에게도 광고 묶음의 **관심**(저장 수 · 오늘 연 수)을 보인다(매물 찾기 화면과 같다).
2. 가격 비공개 광고도 빌탐정매물에 넣는다. 대표가격은 비우고 `광고.가격공개: false`.
3. 고객 조회의 문의 묶음에 **문의 본문**을 싣는다.
4. 고객 모드에도 매물유형 · 건폐초과 · 용적초과를 연다.
