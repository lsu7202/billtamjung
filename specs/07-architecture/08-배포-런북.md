## 구성

```
Firebase Hosting  (frontend/dist · /api/** → Cloud Run rewrite)   ← firebase.json
Cloud Run: bt-api (min=1 · max=4 · 1vCPU/1Gi · --no-cpu-throttling)
Cloud SQL: bt-pg  (PostgreSQL 16 + PostGIS · db-custom-1-3840 · asia-northeast3)
GCS: <project>-bt-artifacts  (사진 photos/* · 보고서 reports/*)
Secret Manager: bt-jwt-secret
```

- **Redis 없음(의도)**: 세션=JWT 무상태 · 캐시=버전키 인메모리(인스턴스 독립 정합) · 잡=BackgroundTasks.
- **`--no-cpu-throttling` 필수**: 보고서 생성이 응답 후 BackgroundTasks로 돌므로 CPU 항시 할당.
- **스토리지**: `app/core/storage.py` — `BT_GCS_BUCKET` 설정 시 GCS, 미설정 시 로컬(개발). 사진·PPT 공용.
- PPT 템플릿은 이미지 내장(`backend/app/assets/R_example.pptx`) — specs 참조 아님.

## 순서 (처음 1회)

```bash
# 0) 배포용 계정 로그인 + 결제 연결된 프로젝트 준비(콘솔)
gcloud auth login

# 1) 인프라 생성 (~10분 · Cloud SQL 생성이 느림)
PROJECT=<id> DB_PASS=<강력한비번> scripts/deploy/setup_infra.sh

# 2) DB 적재 (덤프 = backups/billtamjung.dump · 510MB · ~수십 분)
brew install cloud-sql-proxy   # 미설치 시
PROJECT=<id> DB_PASS=<비번> scripts/deploy/load_db.sh

# 3) API 배포 (FRONTEND_BASE는 일단 Hosting 기본 도메인 예상값)
PROJECT=<id> DB_PASS=<비번> FRONTEND_BASE=https://<project>.web.app scripts/deploy/deploy_api.sh

# 4) 프론트 배포
firebase login && firebase use --add <프로젝트id>
scripts/deploy/deploy_web.sh

# 5) 도메인 확정 후 API 재배포(CORS·OAuth 콜백 갱신) — FRONTEND_BASE 바꿔 3) 재실행
```

## 보안 상태 (2026-08-03 점검·실측)

- **SSH 없음**: Cloud Run=서버리스(VM·포트 자체가 없음). 접속할 서버가 없다.
- **DB**: 공인IP 있으나 authorized networks 0개 → 직접 접속 불가. 유일 경로=IAM 인증 Cloud SQL 커넥터(개발자 gcloud / Cloud Run SA).
- **API**: 전 엔드포인트 JWT(argon2 해싱) · CORS=web.app 한정 · statement_timeout 30s · max-instances=4.
- **rate limit**(v4, `core/ratelimit.py`): per-IP 로그인 10/분·가입 5/분·비번재설정 5/분 → 429+Retry-After. 인메모리(인스턴스별)라 실효한도 최대 4배 — 베타 충분, 정식은 Cloud Armor/Redis.
- 남은 구멍: 가입 완전 오픈(체험크레딧 파밍 가능) — 베타 가입코드 게이트 검토.

## 실배포 트러블슈팅 (2026-08-03 실측 — 스크립트 반영됨)

| 증상 | 원인 | 해결 |
|---|---|---|
| Cloud SQL create 400 Invalid Tier | 신규 기본=ENTERPRISE_PLUS가 db-custom 거부 | `--edition=enterprise` |
| 배포 시 secret Permission denied | compute SA에 접근권 없음 | secretAccessor + 버킷 objectAdmin 부여 |
| 컨테이너 부팅 실패(int parse) | asyncpg가 `@/db?host=/cloudsql/..` DSN에서 비번을 포트로 오파싱 | 소켓경로 percent-인코딩해 host 위치에 (`@%2Fcloudsql%2F..%3A..%3Abt-pg/db`) |
| --set-env-vars Bad syntax | DSN의 `@`가 구분자 충돌 | 구분자 `^##^` |
| addFirebase 403 지속 | 새 계정 Firebase 약관 미동의 | 콘솔에서 프로젝트 추가(약관 동의) 1회 |
| 웹에서 /api/* 전부 404 | Hosting run 리라이트는 경로 그대로 전달(vite는 /api 스트립) | 라우터 이중 등록(맨몸+`/api`) — main.py |
| 수정 배포 후에도 404 지속(0.02s 응답) | Hosting CDN이 이전 404를 엣지 캐시 | API 전 응답 `Cache-Control: private, no-store` 미들웨어 + Hosting 재배포(퍼지) |
