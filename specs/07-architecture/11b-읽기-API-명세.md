# 11b · 모델용 읽기 API 명세(스키마 · 응답 · 오류)

> 2026-10-04. [11a](11a-스킬-조회.md)의 이름 사전 · 결정을 실제 도구 스키마로 옮긴 것. **구현 정본.**
> 도구 셋: `buildings`(건물 조회) · `customers`(고객 조회, 중개사만) · `me`(내 정보, 고객만).

## 1. 공통 규칙

### 1-1. 모드가 스키마를 고른다
`GET /ai/tools`와 대화 엔진은 토큰의 계정 종류로 `BROKER` / `CUSTOMER` 묶음 하나를 고른다. 같은 도구라도 모드마다 **다른 스키마**가 나간다(이름 · 출처 enum · 손잡이 수가 다름). 요청에 모드 칸은 없다.

### 1-2. 이름 하나 = 손잡이 하나
`조건`의 값은 이름마다 아래 넷 중 하나다. 이름의 갈래는 사전(11a §1-4 · §2-2)이 정한다.

| 갈래 | 모양 | 뜻 |
|---|---|---|
| 수 | `{"이상": n, "이하": n}`(하나만 줘도 됨) · 날짜 칸은 `{"이후": "YYYY-MM-DD", "이전": …}` | 범위로 거른다 |
| 목록 | `{"값": ["A","B"]}` · `{"값": [["A","B"],["C"]]}`(주용도 · 입주업체만) · `{"없음": true}` | 하나라도 맞으면 / (A 그리고 B) 또는 C / 비어 있는 것 |
| 어디 | 문자열 | 지역 · 주소 · 건물번호 · 필지번호 · 법정동코드 |
| 보기만 | `{}` | 거르지 않고 줄에 싣는다 |

- 어느 갈래든 `{}`를 주면 **보기만**이다. 걸고 싶으면 손잡이를 단다.
- `조건`은 늘 목록이다. 목록 사이는 「또는」, 한 항목 안은 「그리고」.
- 보기만 할 칸 · 묶음도 `조건` 안에 이름을 `{}`로 댄다(`{"층별": {}}`). 따로 `보기` 인자는 두지 않았다(구현 10-04) — 걸 조건과 볼 칸이 한 사전이라 두 자리에 적을 일이 없다.

### 1-3. 응답 머리
```json
{ "단위": "면적 ㎡ · 금액 원 · 평단가 원/평 · 공시지가 원/㎡ · 거리 m · 비율 % · 층수 층 · 유동인구 명/일" }
```
줄마다 단위를 되풀이하지 않는다. 빈 값(null)은 키째 뺀다. 미지정은 비운다는 원칙과 같다.

### 1-4. 잘림
응답 하나는 약 6,000토큰 안에 든다. 줄 수 = 예산 ÷ (줄 바탕 + 칸 수 × 칸당 값)으로 서버가 정한다(지금 `_rows_for` 그대로). 묶음마다 `전체`(걸린 수)와 `보여준수`를 같이 준다. 잘렸으면 모델이 정렬을 바꾸거나 조건을 좁힌다.

### 1-5. 오류
도구 오류는 HTTP 오류가 아니라 **결과 안의 `오류`**로 돌려준다. 모델이 읽고 고쳐 다시 부르게 하려는 것이다.
```json
{ "오류": { "코드": "UNKNOWN_NAME", "이름": "급함도", "가까운": ["급함"] } }
```
| 코드 | 언제 |
|---|---|
| `UNKNOWN_NAME` | 사전에 없는 이름(고객 모드의 팀 이름 포함) |
| `BAD_KNOB` | 갈래와 안 맞는 손잡이(수에 `값`, 목록에 `이상`) |
| `BAD_VALUE` | 목록 값이 갈래 값에 없음. `가까운`에 후보 |
| `NOT_FOUND` | 건물번호 · 고객번호 · 저장조건이 없거나 내 것이 아님 |
| `FORBIDDEN` | 모드가 못 쓰는 것(고객이 `고객` 손잡이 · 남의 저장조건) |
| `TOO_WIDE` | 지역 · 조건 없이 전 서울 일반을 정렬 없이 부름 |

## 2. `buildings` · 건물 조회

### 2-1. 입력 스키마
```jsonc
{
  "type": "object",
  "properties": {
    "조건": { "type": "array", "items": { "type": "object", "properties": { /* 이름 → 손잡이. 모드별 사전에서 생성 */ } } },
    "출처": { "type": "array", "items": { "enum": ["내매물","빌탐정매물","네이버매물","일반"] } },  // 고객: ["빌탐정매물","일반"]
    "고객": { "type": "integer" },        // 중개사만(고객 스키마엔 없음)
    "저장조건": { "type": "integer" },
    "정렬": { "enum": [ /* 수 · 날짜 이름 중 정렬 가능한 것 */ ] },
    "차순": { "enum": ["내림차순","오름차순"] }
  },
  "required": ["조건", "정렬", "차순"]
}
```
- `출처`를 안 주면 모드의 출처 전부.
- `고객` · `저장조건`을 주면 서버가 그 조건을 펼쳐 `조건` 목록에 「또는」 갈래로 더한다. 같이 준 `조건`이 있으면 펼친 갈래마다 그 조건을 「그리고」로 붙인다(「이 고객 조건 + 명도 쉬움」).
- 정렬 기본값은 없다. 무엇으로 세울지가 곧 무엇을 보느냐라 물음이 정한다(지금 규칙).

### 2-2. 출력 스키마
```jsonc
{
  "단위": "…",
  "검색": [ {                                      // 조건(또는 펼친 갈래)마다 한 항목. 하나여도 목록
    "조건": { … },                                  // 항목이 둘 이상일 때만 — 물은 그대로
    "펼친조건": "종로구 준신축(13)",                 // 고객 · 저장조건을 펼쳤을 때만
    "지역": ["서울 종로구"],                         // 지역을 무엇으로 읽었나
    "내매물":     { "전체": 4, "목록": [ 줄 ] },              // 중개사만
    "빌탐정매물": { "전체": 37, "보여준수": 20, "목록": [ 줄 ] },
    "네이버매물": { … },                                       // 중개사만
    "일반":       { "전체": 2311, "보여준수": 20, "목록": [ 줄 ] }
  } ]
}
```
**줄**
```jsonc
{
  "건물번호": "10021100209425", "주소": "서울특별시 종로구 누상동 94번지",
  "대표가격": 950000000, "대표가격출처": "매매가",      // 매매가 | 광고 | 네이버 | 추정
  /* 물어본 칸 */ "대지면적": 36.1, "명도": "쉬움",
  "광고": { "매매가": 1050000000, "가격공개": true, "중개사": "…", "사무소": "…", "올린날": "2026-09-30", "광고수": 2, "관심": {"저장": 5, "오늘": 12} },
  "층별": [ … ], "시세": { … }                          // 묶음은 조건에 이름을 댔을 때만
}
```
- 팀 칸은 `내매물` 줄에만 키가 생긴다. 다른 출처 줄에선 `보기`에 이름이 있어도 키를 안 만든다.
- 묶음은 줄마다 붙는다. 무거운 묶음(주변동향 · 주변매각 · 주변실거래)을 여러 줄에 달면 예산 안에서 줄 수가 준다(지금 `_sec_chars` 규칙).

### 2-3. 묶음 손잡이(지금 그대로)
| 묶음 | 손잡이 |
|---|---|
| 주변동향 | 반경 · 연수 · 갈래 |
| 주변실거래 · 주변매각 | 반경 · 연수 |
| 공시지가추이 · 실거래이력 | 연수 |
| 시세(새로) | 연수(매매 이력 기간) |
묶음 손잡이는 조건 안에 `{"주변동향": {"반경": 300, "연수": 1}}` 꼴로 준다. 계약상대 · 계약가 · 계약일 · 중도금 · 잔금일은 **짝** 묶음에 실린다(채택된 줄).

## 3. `customers` · 고객 조회(중개사만)

### 3-1. 입력 스키마
```jsonc
{ "type": "object",
  "properties": {
    "조건": { "type": "array", "items": { "type": "object", "properties": { /* 11a §2-2 사전 */ } } },
    "고객": { "type": "integer" },
    "보기": { "type": "array", "items": { "enum": [ /* 칸 + 묶음: 조건 · 문의 · 메모 · 담긴매물 */ ] } },
    "정렬": { "enum": ["등록일","희망매매가","시드","이름"] },
    "차순": { "enum": ["내림차순","오름차순"] } },
  "required": ["정렬","차순"] }
```
`희망매매가` 조건은 **겹침**으로 건다. `{"이하": 50억}`이면 고객의 최소가 50억 이하인 사람(상관없음 포함)이 걸린다.

### 3-2. 출력
```jsonc
{ "고객": { "전체": 23, "보여준수": 20, "목록": [
  { "고객번호": 12, "이름": "김민수", "전화있음": true,
    "희망매매가": {"최소": 3000000000, "최대": 5000000000},   // 상관없음이면 "상관없음"
    "조건": [ {"저장조건": 31, "이름": "종로 수익형", "요약": "종로구 · 대지 150㎡ 이상 · 30~50억"} ],
    "문의": [ {"날짜": "2026-10-02", "유형": "매수", "상태": "상담중", "건물번호": "…", "본문": "…"} ],
    "메모": [ {"날짜": "…", "글": "…"} ],
    "담긴매물": [ {"건물번호": "…", "주소": "…", "매수희망가": …, "채택": false} ] } ] } }
```
`조건[].저장조건` 번호를 `buildings.저장조건`에 그대로 넣는다.

입력: `{}`(본인 고정). 출력:
```jsonc
{ "내투자": { "희망매매가": {"최소": …, "최대": …}, "시드": …, "목표": ["수익률"], "원하는지역": ["종로구"],
             "매수시기": "6개월 안", "건축의사": "없음", "개인법인": "개인", "매입경험": "처음" },
  "찾는조건": [ {"저장조건": 40, "이름": "대화에서", "요약": "…"} ],
  "관심매물": [ {"건물번호": "…", "주소": "…", "광고매매가": …} ],
  "구해요":   [ {"건물번호": "…", "상태": "열림", "제안수": 2, "마감": "2026-10-30"} ],
  "보낸문의": [ {"날짜": "…", "건물번호": "…", "상태": "상담중"} ] }
```

## 5. HTTP(점검 · QA용)
모델은 HTTP를 안 쓴다(같은 프로세스 함수). 아래는 사람이 같은 함수를 curl로 확인하는 길이다. 대화 엔진과 **같은 모드 · 같은 거름**을 탄다.

| 메서드 · 경로 | 인증 | 몸통 | 응답 |
|---|---|---|---|
| `GET /ai/tools` | `any_user` | | 내 모드의 도구 스키마 |
| `POST /ai/read/buildings` | `any_user` | §2-1 | §2-2 |
| `POST /ai/read/customers` | `current_user`(중개사) | §3-1 | §3-2 |
| `GET /ai/read/me` | `any_user`(고객) | | §4 |

옛 `POST /ai/search` · `GET /ai/buildings/{pk}`는 `/ai/read/buildings`로 합치고 지운다.

## 6. 예시

**① 고객: 「종로에서 30억대 매물 있어?」**
```json

```

## 8. 검증(qa/ai)
- 모드별 스키마 스냅샷: 고객 스키마에 팀 · 네이버 이름 · `고객` 손잡이 · 내매물/네이버 출처가 **하나도 없다.**
- 고객 토큰으로 팀 이름을 조건에 → `UNKNOWN_NAME`.
- 중개사 응답에서 내매물이 아닌 줄에 팀 칸 키가 0개(전 줄 훑기).
- 응답 어디에도 `전화` 키가 없다(전 키 훑기).
- 매각됨 매물이 내매물에 없다.
- `고객: n` 펼친 결과 = 그 고객 조건들을 손으로 걸어 합친 결과(건물번호 집합 같음).
- 같은 조건의 화면 API(매물 탐색 · 매물 찾기) 결과와 건물번호 집합이 같다. 화면과 모델이 갈라지지 않는다.
- 예시 ①~④가 오류 없이 돈다.

## 9. 10-04 근본 정리(승인 · 구현됨)
위 본문보다 이 절이 앞선다.
- **이름 사전 = 선언 표 한 장**(`backend/app/ai/catalog.py`). 스키마 · 조건 옮기기 · 줄 칸 · 정렬 · 모드 열림이 전부 여기서 나온다. 값 목록은 손으로 적지 않고 정본에서 읽는다(ref.enums · 사무소 상태 · 팀원 · 저장조건 · 지역). 스키마는 사람마다 다르다. 전체 목록은 [11c](11c-읽기-스키마-전체.md)(표에서 뽑은 문서).
- **내부 번호를 안 낸다.** 건물은 주소, 사람은 이름(고객은 같은 이름이 둘이면 「이름 · 등록일」), 담당자는 이름. 건물번호 · 필지번호 · 고객번호 · 계정 번호는 응답에도 입력에도 없다.
- **주소 해석은 함수 하나**(`search.addr_keys` · `_addr_cond` · `pks_by_addr`) — 지번 · 도로명 둘 다(0223 `master.road_key`). 검색 · 셈 · 자료 지도가 같이 쓴다.
- **같은 지번에 건물이 여럿**이면 줄에 주용도 · 연면적 · 지상층수가 붙는다. 좁히려면 그 이름을 조건에 건다. invest · develop 의 `건물` 은 건물 조회 조건 항목과 같은 모양, 자료 지도는 `addr` + `use` · `area`.
- **기본 출처 = 화면**: 중개사 내매물 · 빌탐정매물 · 네이버매물, 고객 빌탐정매물. 안 본 일반은 **수만** 동봉(`"일반": {"전체": N}`).
- **넓은 검색 막이는 일반에만**: 일반을 보려면 지역 · 주소 · 법정동코드(또는 저장조건의 지역)가 있어야 한다 → 없으면 `TOO_WIDE`. 내 매물 · 광고 · 네이버는 어디 없이도 돈다.
- **한 채를 짚으면**(주소) 매각된 내 매물도 내매물로 나온다.
- 회귀: `qa/run.sh ai` = `qa/ai/qa_read.py`(26개).

## 10. 매물 중심 · 매물 하나에 매매가 하나(2026-10-05 · 0226 · 0227 · 승인 · 구현됨)
§9 와 그 앞 본문보다 이 절이 앞선다(§9 의 「기본 출처」 · 「대표가격」, 0224 의 `sale_prices` 는 없어졌다). 원천 스키마 정본은 [매물-중심](../04-data/매물-중심.md).

**원천**
- 매물 = `app.listings`(주인 사무소 · 건물 · 매매가 · 평단가). 종류 칸은 없고 주인으로 가른다. 수집 매물의 주인은 수집 사무소 「네이버」(`teams.system`).
- 관리 칸은 `listing_office`(1:1), 수집 정보는 `listing_crawl`(수집일 · gone_on), 광고 `ads` 는 노출 기록만.
- 누가 무엇을 보나 · 순번은 `app.listings_now(사무소, 중개사인가)` 한 곳이 정한다. 순번 = 내 매물 → 다른 사무소 광고 매물(최근 순) → 수집 매물.
- 매물은 등록으로만 생긴다. 등록 안 한 건물엔 매물관리 칸 · 층별 임대 · 사진을 못 적는다.

**모델 읽기**
- 한 줄 = 매물 하나. 뼈대는 `주인`(「내 매물」 · 사무소 이름 · 「네이버」) · `주소` · `매매가`(값 하나). 출처 구획 · `출처` 인자 · `대표가격` 은 없다.
- 주인마다 딸린 칸: 다른 사무소 = `중개사` · `관심`, 네이버 = `수집일` · `광고수`.
- `추정가` · `추정임대료`는 사람이 물을 때만 부른다. 매매가를 물으면 부르지 않는다.
- 어느 범위까지 볼지는 조건 이름 `매물`(내 매물 · 매물 · 전체). 팀 칸을 걸면 내 매물만 남는다.
- 지도 핀은 건물마다 하나 · 그 건물 1번 매물의 매매가(없으면 「미정」). 카드도 같은 규칙. 추정가로 대신 채우지 않는다.
- invest · develop 는 `거래금액` 이 없으면 매물마다 한 줄씩 센다.
- 전체 목록은 [11c](11c-읽기-스키마-전체.md).

**화면**
- 카드 · 목록은 매물 하나에 하나. 지도는 1번 매물만 그린다(수를 그리지 않는다).
- 매물 모달 · 사이드바에서 고치는 매매가는 내 매물의 값. 사이드바 「이 건물의 매물」에 다른 매물이 순번대로 선다.
- 필터 「매매가」(`price_min/max`)는 매물마다 건다.
