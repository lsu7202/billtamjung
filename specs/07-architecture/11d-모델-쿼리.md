# 11d. 모델 쿼리 — 표를 열고 모델이 SQL 을 쓴다

> 2026-10-07 대표와 정함. 시험판(0238 · `query` 도구 · 매물 표 하나)은 로컬에 있다. 이 문서는 그다음 판이다.
> 11b(읽기 API 명세)의 `buildings` 를 대체한다. 화면 이전은 모델 시험이 잘 된 뒤 따로 잡는다.

## 1. 왜

- 모델은 `buildings` 의 손잡이(칸 하나 × 상수) 안에서만 답했다. 칸끼리 · 줄끼리 견주기, 모으기, 매물 밖의 물음(「종로구 실거래 몇 회」)이 막혔다.
- 10-06 「네이버 매매가보다 비싼 내 매물」: `buildings` 로 도구 12번 소진 · 빈 답 → `query` 시험판으로 도구 1번 · 47건(DB 대조 일치).
- 9월 SQL 실패(37동/35동 · LIMIT 3 → 「10동」 · 단위 · 탐색 바퀴)는 **원본 표 45개를 연 탓**이었다. 이번엔 이어 붙인 표만 연다.

## 2. 도구 둘

| 도구 | 하는 일 | 입력 |
|---|---|---|
| `query` | 조건으로 찾기 · 세기 · 견주기 · 한 곳 보기 전부 | `sql` 한 문장 |
| `look` | **쿼리로 하면 안 되는 것만** 보기 | 대상(주소 · 지번코드, 최대 5) + 묶음 |

- 가르는 기준: 조건으로 걸 일이 있으면 표. 걸면 안 되는 것만 `look`.
- `look` 묶음 = 유동인구 · 시간대별유동인구. 조건으로 걸면 안 된다(대표 두 번 지적). 표로 열면 막을 수 없다.
- 개인정보: 이름 · 전화는 연다. 주민번호급(주민 · 외국인등록 · 여권 · 면허 · 카드 · 계좌)만 나가는 문(`scrub`)이 지운다.

## 3. 표

### 3-1. 두 층

```
원본 표
  ↓
층 1  기본 뷰 — 영어 이름 · 좌표 포함 · 칸 전부   ← 화면 검색 · 건물 시트 (이전 때)
  ↓  이름 바꾸기 · 칸 고르기 · 나누기만(새 계산 없음)
층 2  모델 뷰 — 한글 이름 + 단위 · 좌표 없음      ← query
```

층 2는 층 1에서 이름만 바꾸므로 화면과 모델의 값이 갈릴 수 없다.

### 3-2. 공통 규칙

- 잇는 열쇠는 **지번코드**(PNU 19자리). 모든 표에 있다. 건물 단위 표는 건물ID 도.
- 칸 이름 = 한글 + 단위(`_원` `_㎡` `_m` `_pct` `_대`).
- 사실 하나는 한 곳에: 땅 값은 지번, 건물 값은 동. 매물에 대지면적 · 연면적을 다시 싣지 않는다.
- 모르는 값은 null.

- 매물: 네이버도 매물 한 줄(0226 유지). 「매매가」는 하나. 「주인」은 쓰지 않는다 — 사무소(원천 이름) + 내매물(보는 사람 기준 참/거짓)으로 가른다. 수집일 = 매매가기준일이라 따로 두지 않고, 광고수는 뺀다.
- 추정을 따로 표로 둔 이유: 일부러 이어 붙여야만 나온다. 묻지 않은 추정가가 섞이지 않고, 꺼내면 평단가 · 공시비율이 함께 온다.
- 표마다 성격 한 줄을 설명에 싣는다(지시가 아니라 사실). 예: `임대: 사무소가 적은 실제 계약` · `임대매물: 네이버 임대 광고. 공실에 내놓은 값` · `추정: 빌탐정 추정가`. 「얼마 받을까」에 두 길(사무소 내역 · 주변 임대매물 셈)을 모델이 출처를 갈라 말하게 하려는 것. 추정임대는 없다.
- 임대와 임대매물을 나눈 이유(10-07 대표): 임대는 지금 든 임차인의 계약, 임대매물은 **공실에 올린 광고**다. 한 표에 두면 같은 층의 업체와 광고 월세를 이어 「이 업체가 이 월세를 낸다」고 특정하게 된다. 네이버는 호실 · 업체를 모른다. 면적은 소수 둘째 자리로 낸다(원천에 `25.789999…`).
- 동 표엔 표제부 값을 **번호 · 코드 성격만 빼고 전부** 연다(10-07 대표). 화면이 안 그려도 뷰에 있으면 나중에 화면 · 다른 API 가 칸 하나 고르면 된다.
  표제부 원문 48키는 이미 동마다 있다(`master.building_ledger_raw` · 0164 · 585,731줄 = buildings 와 1:1). 층 1 동 뷰가 `rec->>'키'` 를 꺼내 칸으로 세운다(대장 재빌드 불필요):
  내진적용 · 내진능력 · 지붕 · 기타구조 · 비상용승강기 · 최근대수선구분 · 대수선이력 · 총동연면적 · 세대수 · 가구수 · 호수 · 허가일 · 착공일 · 동명 · 주부속구분 · 사용승인일 정밀도.
  `ledger_basic` 에서 이어 붙이는 것: 건물명 · 대장종류 · 외필지수 · 지역 · 지구 · 구역 이름.
  빼는 것: 생성일자 · parent_pk · 각종 코드(sgg · bjd · zone · district · area 코드). 단지(`building_complex`) · 사라진 건물(`building_closed`)은 단위가 달라 동 표에 섞지 않는다.
- 공공지목을 따로 둔 이유: `buildings` 의 「지목 안 걸면 10종 뺌」을 SQL 에선 끼워 넣을 자리가 없다. 지목 기준이지 소유 기준이 아니다(그래서 「국공유지」라 부르지 않는다).

### 3-4. 함수

| 함수 | 돌려주는 것 |
|---|---|
| `반경(지번코드, 미터)` | `(지번코드, 거리_m)` 표. 공간 인덱스를 타게 짜 둔다. 3,000m 까지 |
| `지번(주소)` | 지번코드. 지번 · 도로명 · 줄임 주소. 못 찾으면 0건이 아니라 오류 |

모델 계정에 좌표 · PostGIS 함수는 열지 않는다. 이 둘만 연다.

## 4. `query` 요청 · 응답

**선언**: `name: query` · `description:` 표마다 `이름(칸, 칸{값 목록}, …)` 한 줄 + 함수 둘 · `input_schema: {sql: string}`.
값 목록은 정본(ref.enums · 사무소 상태 사전 · 팀원 · 그 사용자의 사무소 이름)에서 뽑는다. 너무 많은 칸(주용도 · 업종 · 규제)은 싣지 않는다.

**요청**: `{"sql": "SELECT …"}` — 다른 칸 없음.

**처리**: 사무소 줄(매물 · 임대 · 짝 · 고객)을 `bt_query` 접속의 임시 표에 넣는다 → 뷰는 권한으로 연다 → 읽기 전용 · 준비문(한 문장) · 10초 → 전체 줄 수를 세고 예산(6,000토큰)만큼 담는다.

**응답**
```json
{"전체": 47, "보낸수": 47, "칸": ["주소", "매매가_원"], "줄": [["서울특별시 중구 북창동 104", 50000000000]]}
```
실패 `{"error": "DB 문구 (자리 N)"}` · 10초 넘으면 「10초 안에 안 끝났다」. 실패도 도구 1번으로 센다.

**다음 턴에 넘기는 것**: SQL 원문 + 전체 수 + 열쇠 칸(지번코드 · 매물ID · 건물ID · 주소)을 순서대로 수십 줄까지. 열쇠가 없으면 SQL 로 다시 돌린다.

## 5. `look` 요청 · 응답

```json
요청 {"대상": ["종로2가 71-6"], "묶음": ["유동인구"]}
응답 {"대상": [{"지번코드": "…", "주소": "…", "유동인구": {"칸": ["주간_명","야간_명"], "줄": [[52000, 18000]]}}]}
```
응답 꼴은 `query` 와 같은 「칸 · 줄」.

## 6. 화면으로 이어지나 (10-07 실측)

| 경우 | 지금 `/search` | 뷰 모양 쿼리 |
|---|---|---|
| 종로구 매물 · 대지 200㎡+ | 1.58s | 1.29s |
| 종로구 전체 땅 · 대지 200㎡+ | 1.45s | 1.95s (필지 구·동 인덱스 없음) |
| 종로구 실거래 | 2.35s | 0.33s |

- 쓸 수 있다. 화면 검색은 「층 1 을 읽고 조건 · 정렬 · 페이지만 붙인다」로 바뀌고, 응답 모양은 그대로 둘 수 있다(프론트 무변경).
- 매물 탐색 · 매물관리 표 · 매물 찾기 → 층 1 매물 / 탐색 전체 → 지번 + 매물 / 실거래 탭 → 실거래 / 건물 시트 → 지번 · 동 · 층별 · 업체 · 임대.
- 10-06 에 고친 느린 경우 셋(16s · 27s · 44s)은 이전 때 다시 잰다.

## 7. 남은 결정

- 고객 저장 조건: 화면 필터 JSON 이라 SQL 로 바로 못 쓴다.
- 영역(「사대문 안」): 이름 → 지번코드 함수 + 공식 경계. 복잡해서 미룸(10-07).
- 실거래 범위 · 기준일 고지: 하지 않는다. 다음 파이프라인에서 실거래 여덟 갈래 전부 수집으로 간다(docs/할일.md).
