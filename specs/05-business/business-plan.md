# 빌탐정 사업 운영 계획

> **역할**: "사업을 어떻게 효율적으로 운영할까"의 **주(主) 서사**. MVP 출시→테스터→역할→결제→가격기준→손익분기 흐름.
> 상세는 참조: 과금=`credit-policy.md` · 기능범위=`mvp-scope.md` · 성장=`marketing-aarrr.md`.
> 상태: v0 초안 · 2026-07-06. 수치(가격·크레딧양·BEP)는 **베타 실측 후 확정**.

## 1. 사업 모델 (한눈에)

- **무엇**: 서울 전체 건물 데이터 위에서 돌아가는 **검색 + 분석 SaaS**. (밸류맵/디스코류 + 중개 워크플로우)
- **타깃**: **솔로 상업용 빌딩 중개인** (가격 민감, 개인 단위).
- **해자**: ① **검색**(풍부한 건물 데이터 전 필드 검색) ② **분석보고서**. — 매물관리는 검색에 딸린 것(커머디티).
- **과금**: **구독(검색 무제한) + 크레딧(보고서)**. → 상세 `credit-policy.md`

## 2. MVP (베타) — 언제·어떻게·누구·왜

### 2.1 출시 (언제 / 어떻게)
| 단계 | 기간 |
|---|---|
| 개발 (**서울 전체 데이터 적재 포함**) | 7/11 ~ 7/25 · 2주 |
| 내부 테스트·QA·온보딩 준비 | 7/27 ~ 7/31 · 1주 |
| **🚀 베타 출시** | **8/3 (월)** |
| 베타 운영 | 8/3 ~ 8/23 · 3주 |
| 회고 · Go/No-go | 8/24 ~ |

- **무결제 출시** — 결제 시스템 없이 나감. 크레딧은 **그림자 계량**(소비만 기록).

### 2.2 테스터 (누구)
- **지인 체인(지인의 지인) 솔로 중개인 3인.**
- **무료 창립 파트너** — 무료 접근 ↔ **주간 피드백 + 인터뷰** 딜.
- 데이터가 서울 전체라 지역 클러스터링은 필수 아님(활성화는 어디든 가능). 네트워크 기능(위키 등 집단지성)을 초기에 보고 싶으면 같은 지역으로 모으는 건 선택.

### 2.3 MVP의 역할 (왜 = 무엇을 학습)
MVP는 매출이 아니라 **학습 장치.** 검증 우선순위:
1. **활성화** — 첫 검색+보고서로 "좋다" 순간 도달?
2. **유지** — 재방문·습관 (시장이 원하는 제품인지 = 제1 신호)
3. **사용량 실측** — 검색 빈도, **보고서 소비(그림자 크레딧)** → **이게 결제·가격의 근거**
4. **지불의향** — 대화 + 소프트 선약
5. **정성 피드백**

- **기능 범위(무엇을 만드나)** = `mvp-scope.md` 참조. (검색·상세·매물관리·보고서·크레딧계량 ✅ / 결제·팀공유·리퍼럴·알림·서울 외 ⛔)

## 3. 결제 정책 (MVP 학습 기반)

- **구조**: 구독(검색·데이터·관리 **무제한**) + 크레딧(보고서만 소모). 검색=해자라 크레딧 안 물림.
- **소비**: 브리핑 10 / 매물분석(=가치분석)보고서 30 (1:3). 나머지 0.
- **티어 월 크레딧**: 체험판 60(1개월) / 스타터 300 / 프로 900. — 상세·규칙 `credit-policy.md`
- **베타 = 무결제**, 정식 출시 시 **결제 구축 + 베타 유저 창립 할인 전환.**

---

## 4. 가격 결정 기준 (₩ 미정 — 베타 후 확정)

가격은 **3축**으로 정한다:

1. **원가 바닥 (floor)** — 서버 + 보고서 생성비 + 데이터 유지비. → **크레딧당 원가** 산출. *(베타 소비량 × 원가로 실측)*
2. **지불의향 (ceiling)** — 베타 대화·선약에서 "월 얼마면 쓰나".
3. **경쟁·시장** — 유사 서비스(밸류맵/디스코 등) 가격대 참고.

→ **원가 위에서, 지불의향·경쟁을 참고**해 티어 가격 결정. 크레딧 값을 원가에 비례시키면 마진 투명.

---

## 5. 손익분기점 (BEP)

**계산 틀** (수치는 베타 실측 후):

- **고정비(월)** = 서버 기본 + **데이터 적재·유지**(서울→확장 시 증가) + 개발/운영
- **변동비(유저·월)** = 보고서 생성비 등 (크레딧 소비에 비례)
- **유저당 기여이익** = 구독료 − 유저당 변동비
- **BEP 유저 수** = 고정비 ÷ 유저당 기여이익

> 베타에서 ① 유저당 월 보고서 소비 ② 크레딧당 서버원가 ③ 예상 전환율 을 측정하면 위 식에 대입해 **필요 유료 유저 수**가 나온다. 지역 확장은 고정비(데이터)를 키우므로 **지역별 BEP**로도 봐야 함.

---

## 6. 성장 (마케팅 요약)

- 좁고 신뢰 기반 시장 → **입소문(추천)이 엔진**(유료광고 아님).
- 순서: **활성화·유지 먼저 → 추천 → 획득 → 수익.**
- 획득 = **지인 소개**. 유지 = **검색 습관화**. 확산 = **크레딧 추천보상 + 보고서 입소문**.
- 상세 = `marketing-aarrr.md`

---

## 7. 확장 로드맵

- **데이터 커버리지**: 서울(MVP) → 수도권 → 전국. *지역 = 데이터 적재·유지 원가 = 고정비 증가.*
- **시스템**: 결제/구독/티어 UI(정식 출시) → 팀 공유(대표+직원) → 리퍼럴·위키 크레딧 보상(밀도 후).
- **가격/BEP**: 베타 실측 → 가격 확정 → 지역 확장마다 BEP 재계산.
