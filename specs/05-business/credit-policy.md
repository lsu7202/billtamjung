# 크레딧 정책 (v0 초안)

> **상태**: 초안 · 2026-07-06. **가격(₩)은 미정** — 본 문서는 크레딧 *구조*만 정의.
> 모든 수치는 **초기 가설 → 베타 실측 소비량으로 보정**.

---

## 0. 과금 모델 (2단)

```
[구독 = 티어]  검색 · 데이터 · 매물관리 무제한   ← 구독하는 "이유"(해자), 크레딧 안 물림
[크레딧]       브리핑자료 + 매물분석(=가치분석)보고서   ← 원가 있는 딜리버러블만 소모
[무과금]       유동인구(수기입력) 등
```

**핵심 원칙**
- **해자 = 검색.** 검색은 초고빈도 행동이라 크레딧을 물리면 (a) 해자 행동에 세금, (b) 합산 착시, (c) 사용 난이도↑. → **검색은 항상 무제한.**
- **원가 있는 것에만** 크레딧. 지금은 사실상 **보고서 생성**이 유일한 실비.
- 크레딧 = **하나의 통화** (보고서 소비 + 위키 노동 보상 + 추후 구매)로 통일.

## 1. 소비 (sinks)

| 항목 | 크레딧 | 비고 |
|---|---|---|
| **브리핑자료** 생성 | **10** | 기초 PPT |
| **매물분석보고서(=가치분석)** 생성 | **30** | 심화 · 브리핑과 1:3 |
| 검색 · 매물관리/등록 · 상세열람(S02) · 주변시세분석(S03) · 유동인구 수기입력 | **0** | 무과금 |

> ⚠️ 주변시세분석(S03)이 향후 외부 데이터 조회로 **실비**가 붙으면 소액(예 1~2) 후보. 현재 0.

## 2. 획득 (faucets)

| 경로 | 크레딧 | 활성 시점 |
|---|---|---|
| 티어 월 지급 | §3 | 상시 |
| **위키 기여** (수정이력 **채택**분만) | **2~5 / 채택** | 밀도 생기면 on — **베타엔 dormant** |
| 추가 구매(top-up) | — | 추후(가격 정책 시) |

> - **채택된 기여만** 보상 → 쓰레기 입력 게이밍 방지 (수정이력 최다값 합의 = 검증 장치).
> - 위키 = "비밀 정보"가 아니라 **"사실이지만 조사 노동이 드는 정보"** → 노동을 크레딧으로 보상하는 구조.
> - 1~3인 베타에선 위키 밀도 제로 → **설계만 해두고 비활성**.

## 4. 규칙

- **월 지급분 = use-it-or-lose-it** (월말 소멸). **위키기여·구매 크레딧은 이월/비소멸**(노동·유상 보상이라).

### 4.1 원장 구조 *(확정 2026-07-19 — 아키텍처 전제)*

**① 유형별 buckets 필수 — 단일 `balance` 컬럼으로는 구현 불가**
위 소멸 규칙이 유형별로 다르므로, 잔액을 하나의 숫자로 두면 "이 40크레딧이 월지급분(소멸)인지 위키적립분(이월)인지" 판정할 수 없다.

| bucket | 소멸 |
|---|---|
| `monthly` (플랜 월 지급) | **월말 소멸** |
| `earned` (위키 기여 적립) | 이월 |
| `purchased` (구매) [정식] | 이월 |

- 소비 차감 순서 = **소멸 임박분 우선**(`monthly` → `earned` → `purchased`). 안 그러면 소멸될 크레딧이 남고 이월 크레딧이 먼저 닳는다.
- 표시 잔액 = 세 bucket의 합.

**② 원장은 append-only 거래 로그**
`(계정, 시각, 유형(지급/소비/적립/소멸), bucket, 증감, 사유, 연결 산출물)`. 잔액은 원장에서 파생(또는 materialized).

**③ ★ 음수 허용 여부 — 베타는 허용, 정식은 금지. 단 DB 제약으로 걸지 말 것**

| | 베타 | 정식 |
|---|---|---|
| 잔액 게이트 | **off** (차단 없음) | **on** (부족 시 생성 거부) |
| 잔액 | **음수 허용** | 0 이상 |

- [규칙] **`CHECK (balance >= 0)` 같은 DB 제약을 걸지 않는다.** 음수 금지는 **서비스 계층 게이트**(소비 전 잔액 확인)로 구현한다.
  - 이유: DB 제약을 걸면 베타에서 음수가 불가능해지고, 반대로 나중에 추가하려면 기존 음수 행 정리가 선행돼야 해 마이그레이션이 생긴다. **게이트 방식이면 정식 전환 = 플래그 켜기**로 끝난다.
- [규칙] **베타에서 잔액이 음수로 내려가는 것을 허용하고 그대로 기록한다.** 0에서 클램프하거나 잔액을 안 건드리면 **초과 사용량이 삭제**되는데, 그것이야말로 베타 그림자 계량의 핵심 학습 지표다("월 900으로 부족하고 −120만큼 더 썼다" → 정식 가격 책정 근거).
- [규칙] 화면 표기는 `잔액 0 · 초과 120` 형태로 음수를 감추지 않되 겁주지 않는다.
- [규칙] **정식 전환 시 베타 잔액은 초기화한다.** 무결제 기간의 잔액은 실제 채무가 아니므로 음수 잔여분을 이월하지 않는다. → 전환 = **게이트 켜기 + 잔액 리셋**, 스키마 변경 없음.
- 크레딧 소진 시 → **보고서 생성만 차단** (다음 달 or top-up). **검색·관리·열람은 계속 무제한.**
- **체험판**: 1개월 풀 검색 무제한 + 60크레딧으로 보고서 맛보기(분석보고서 2건 상당). 종료 시 유료 전환.
- 보고서 생성 시 **"이 보고서 N크레딧 차감"** 확인 → 불투명 미터링 아님.

## 5. 베타 전략

- 베타(지인 1~3인)는 **무료(창립 파트너)** — 피드백 대가. 크레딧은 넉넉히/무제한 부여하되 **소비는 기록**.
- → "솔로 중개인이 월에 보고서 몇 건 쓰나" **실측** → 그 소비 × 보고서 생성 서버원가 = **원가 바닥** → 가격·월 지급량 확정.
- 즉 **가격을 안 정하고도** 크레딧 계량으로 학습 진행.
