## 0. 결제시스템? → **베타엔 도입 안 함**

- 베타 유저 = **무료 창립 파트너**(피드백 대가). 1~3명 매출은 무의미. PG/구독/환불 구축은 제품 검증을 지연.
- **크레딧 원장(부여·소비·잔액 기록) = 필요** / **크레딧 결제(돈으로 구매) = 불필요**.
- **그림자 계량(shadow metering)**: 무제한/넉넉히 주되 **"얼마 소비했을지"만 기록** → 제한·결제 없이 **가격 산정용 실사용 데이터** 확보.
- **지불의향**은 결제 없이: ① 사용량 계량 ② 직접 대화("월 얼마면?") ③ 소프트 선약(창립 할인 전환 의향).
- 결제는 **베타 종료 후, 가격 확정 뒤** 구축 → 베타 유저를 **창립 할인**으로 첫 유료 전환.

## 1. 목표 (검증 우선순위)
1. **Activation** — 아하(검색+보고서) 도달?
2. **Retention** — 재방문·습관 (← 제1 PMF 신호)
3. **사용량** — 검색 빈도, 보고서 수(그림자 크레딧)
4. 지불의향 신호(대화·선약)
5. 정성 피드백(빠진 것·헷갈리는 것)

## 2. 참가자
- **같은 상권 3인**, 지인 체인(warm intro). 무료 창립 파트너.
- 딜: 무료 접근 ↔ **주간 피드백 + 인터뷰**.

## 3. 기간
- **3주** (짧게). W1 활성화 / W2 리텐션 / W3 심화·지불의향.

## 4. 범위
- ✅ 검색(S01/S01b) · 상세(S02) · 매물관리 · **보고서 생성** · **상권 데이터(개발에 포함)** · 크레딧 원장/그림자 계량
- ⛔ 결제/구독/티어 강제 · 리퍼럴 시스템 · 위키 크레딧 보상(밀도 없음)

## 5. 온보딩
관심지역=본인 상권 → 아는 건물 검색("다 있네") → 샘플 보고서 1건(wow).

## 6. 측정
- 로그: 검색 수·저장 매물·보고서 생성·그림자 크레딧·세션 빈도
- 정성: 주간 콜/단톡 피드백 로그
- 성공 임계값 예: 2~3주차 주 N회 검색, 보고서 ≥1건, 주 3일↑ 재방문

## 8. 종료 → 판정 (8/24~)
- **Go 조건**: 리텐션 신호 + 지불의향 + 소비 데이터로 가격/티어 확정
- → 결제 구축 + 베타 유저 **창립 할인 전환**

## 9. 리스크
- 데이터 콜드스타트 → 선충전(개발 포함)으로 방어.
- 3인이라 네트워크 기능 약함 → **단일 사용자 가치 먼저 검증**, 위키/리퍼럴은 이후.
- 스코프 크립 → 베타 빌드 최소화.
