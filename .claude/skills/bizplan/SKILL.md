# 모두의창업 사업계획서

정본 결(結) = `docs/자료/네이처셀.pdf`. 작업 폴더 = `docs/자료/모두의창업/`.

## 0. 먼저 지킬 것

1. **대표가 준 문장은 그대로 쓴다.** 고칠 수 있는 것은 오탈자와 기관 정식 명칭뿐이다.
   고쳤으면 무엇을 왜 고쳤는지 **한 줄로** 보고한다. (실제 예: 스팩→스펙, 부동산평가원→한국부동산원)
2. **시킨 것만 한다.** 「이렇게 먼저 수정해」는 그 부분만 고치라는 뜻이다.
   나머지 절을 손대지 않고, 손대지 않았다고 말한다.
3. **짧게.** 대표의 지적 1순위가 「주저리주저리 적는다」였다.
   한 논점 = 2~4문장. 그 이상이면 뺄 문장이 있는 것이다.
4. **없는 수치를 이름 붙여 지어내지 않는다.** 공표 통계가 없으면 표에 `–` 를 두고,
   문서 끝 「제출 전 확인할 것」에 적는다. 「플랫폼 분야 중소기업 평균」처럼
   있어 보이는 이름을 붙이지 않는다. 대신 실제로 쓴 모집단을 정확히 부른다.
5. **모든 통계·표에 출처를 남긴다.** 시점까지 적는다(2026.09 열람 / 2026년 2분기 기준).

## 1. 텍스트 골격

### 종결과 어법

- **명사·체언 종결.** `~임` `~음` `~함` `~중` `~구조임` `~가능성이 높음` `~로 평가됨`.
  `~이다` `~한다` 를 쓰지 않는다. (대표 지시: 「다 → 임, 음으로 바꿔줘」)
- **예외 둘.** 대표가 직접 준 슬로건·인용문은 존댓말이라도 그대로 둔다.
  마지막 권고·당부 문단만 `~합니다` 로 바꿀 수 있다(네이처셀 5장 말미가 그렇다).
- **단정과 추정을 나눈다.** 사실은 `~임`, 해석은 `~로 판단` `~로 해석 가능` `~가능성이 높음`.
- **접속은 한자어로.** 다만 · 반면 · 따라서 · 한편 · 결국.
  「그리고」 「하지만」 「그래서」 는 되도록 쓰지 않는다.
- **수치에는 단위와 시점을 붙인다.** 「108,319곳(2026년 2분기)」 「16.99%」 「25.7만 건」.
- **굵게는 문장당 한 곳.** 핵심 명사구에만.
- **인용은 「 」.** 낱말을 도드라지게 할 때만.

### 문단과 불릿

- 문단은 2~4문장. 한 문단 = 한 논점.
- 근거·부연이 셋 이상이면 문단 뒤에 **▲ 불릿**으로 내린다. 불릿도 명사 종결.
- 소제목은 `1)` `(1)` `①` + 짧은 명사구. 소제목에 설명을 덧붙이지 않는다.

### 쓰지 말 것 (AI 티가 나는 자리)

| 금지 | 왜 |
|---|---|
| 대시(—)를 연결어로 | 프로젝트 규칙. 쉼표와 마침표로 나눈다 |
| 예고 문장(「세 단계로 나누어 설명함」 「차례로 봄」) | 목차가 이미 말한다 |
| 이음말(「즉」 「정리하면」 「주목할 점은」 「결론적으로」) | 문단이 제 순서면 필요 없다 |
| 표에 있는 값을 본문에서 되읊기 | 표와 글이 같은 말을 두 번 한다 |
| 구어 비유(「굴리다」 「지갑을 열다」 「먹었다」) | 보고서 결이 깨진다 |
| 과장(「압도적」 「혁신적」 「전혀 다른 차원」) | 대표가 직접 쓴 경우만 허용 |
| 영어 직역체(「~하는 시장임」 「~에 있어」 「~를 통해 ~함」 남발) | 어순을 한국어로 다시 짠다 |
| `%p` | 프로젝트 규칙. 「11.2 포인트」 또는 값 자체로 |
| 「미공개」 반복 | `–` 로 둔다 |

## 2. 시각자료 골격

### 공통

- **번호와 이름을 붙인다.** `표 N | 이름` · `그림 N | 이름`. 본문은 그 번호로 부른다.
- **텍스트와 대조된다.** 표·그림은 글이 말한 것을 확인시키는 자리다.
  글에 없는 값을 표가 처음 꺼내지 않고, 표에서 읽히는 값을 글이 되풀이하지 않는다.
  글은 **표에서 안 읽히는 것**(왜 그런가, 그래서 무엇인가)만 쓴다.
- 아래에 8pt 회색으로 `자료:` 줄. 산식이 있으면 한 줄 더.
- 목록형 칸은 끝에 **「등」**을 붙인다. 붙이지 않으면 그게 전부인 줄로 읽힌다.

### 표

- 열은 **최대 5개**. 넘으면 열을 합치거나 뺀다(성격+주요기능처럼 겹치는 열을 먼저 본다).
- 첫 열 = 항목 이름(연파랑 바탕, 남색 굵게, 가운데).
- 헤더 = 남색 바탕 흰 글씨 가운데.
- 숫자·짧은 값은 가운데, 서술은 왼쪽.
- **칸 안에서 낱말이 두 동강 나면 열 너비를 고친다**(「부동산플래 / 닛」이 실제로 났다).
- 강조는 **색 하나**로만. 갈래를 나눌 때는 행 배경을 두 톤으로 칠하고 범례를 단다.
- 없는 값은 `–`.

### 그림(차트)

- 두 축이면 **남색 막대 + 주황 선**. 축 이름을 각 축 색으로 위쪽 좌·우에 둔다.
- 값 라벨을 마크 위에 직접 찍는다. 축 눈금은 회색으로 작게.
- 격자선은 **가로만**, 연회색.
- 강조점 한 곳만 빨강(#C0392B).
- 인쇄 폭에 줄어드니 **SVG 글자는 14~15px**로 크게 잡는다.
- **주장과 축이 맞는지 본다.** 「우상향」을 말하려는데 건수는 내려가면,
  올라가는 축(금액·단가)을 같이 넣거나 문장의 대상을 바꾼다. 그림이 글을 배신하면 안 된다.

### 그림의 갈래

표가 세 개 이상 이어지면 읽는 사람이 지친다. **말하려는 것에 맞는 그림을 고른다.**

| 말하려는 것 | 그림 | 네이처셀의 예 |
|---|---|---|
| 시간에 따른 변화 | 막대+선 콤보 차트(두 축) | 매출액·영업이익 추이 |
| 한 값의 흐름과 사건 | 선 차트 + 이벤트 주석 | 주가 추이에 임상 발표·FDA 미팅 표시 |
| 과정·작동 방식 | **흐름도**(STEP 1→2→3→4) | 조인트스템 작용 기전 |
| 일정·마일스톤 | **타임라인**(가로선 + 위아래 교차 박스) | BLA 허가 로드맵 |
| 무엇이 무엇으로 이루어졌나 | **구성도**(층으로 쌓은 블록) | — |
| 지금과 앞으로의 차이 | **대조도**(위: 지금 / 아래: 우리) | — |
| 몫의 비율 | 누적 가로 막대 | — |

원형 파이는 쓰지 않는다. 조각 크기를 눈으로 못 재고, 인쇄에서 라벨이 겹친다.

### 흐름도

- 단계는 **넷 이하**. 다섯이 되면 묶는다.
- 각 단계 = 원 또는 둥근 사각 + 짧은 명사구 두 줄. 화살표는 한 방향.
- 결과·수치는 해당 단계 아래에 작은 뱃지로 단다(네이처셀은 「1회 투여로 5년 효과 지속」).
- 마지막 단계만 색을 진하게 해 도착점을 표시한다.

### 타임라인

- 가로 축 하나에 점을 찍고, 박스를 **위아래 번갈아** 둔다. 겹침이 사라진다.
- 박스 안에 시점(2026.05)과 사건 한 줄. 둘 다 굵게 하지 않는다.
- 이미 지난 시점과 앞으로 올 시점을 색으로 나눈다. 목표 시점은 빨강.
- 아래에 「회사 발표 기준 목표 일정으로, 실제는 상황에 따라 변동 가능」 같은 단서를 단다.

### 시스템 구성도

**심사위원은 개발자가 아니다.** 「우리가 무엇을 가지고 무엇을 해 주는가」가 읽히면 된다.

- **층 3~4개, 블록 12개 이하.** 위에서 아래로 한 방향.
  예: `자료를 받아 오는 곳` → `빌탐정이 모아 둔 데이터` → `해 주는 일` → `쓰는 사람`
- **영어 약어를 쓰지 않는다.** API · DB · ETL · 파이프라인 · 스키마 · 서버 · LLM 전부 금지.
  「받아 온다」 「모아 둔다」 「계산한다」 「보여 준다」로 쓴다.
- 블록마다 **아는 낱말로 예시 한 줄**을 붙인다(「건축물대장」 「실거래가」 「적정가」).
- 층마다 색 하나. 주인공 층(우리 데이터)만 진하게, 나머지는 옅게.
- 범례 없이 읽혀야 한다. 범례가 필요하면 그림이 복잡한 것이다.
- 양쪽으로 갈라지는 화살표, 되돌아오는 화살표를 만들지 않는다.

### 대조도

- 위 줄 = 지금 하는 방식, 아래 줄 = 우리 방식. 같은 자리에서 시작해 같은 자리로 끝난다.
- 위 줄은 회색, 아래 줄은 색. 길이 차이로 「단계가 줄었다」가 보이게 한다.
- 사라진 단계에 취소선을 긋지 않는다. 아예 없애고, 아래에 「자료를 찾아 옮기는 세 단계가 사라짐」이라고 적는다.

### 그리는 법

- **SVG 를 직접 쓴다.** 파이썬으로 좌표를 계산해 `_chart*.svg` 로 내보내고 크롬으로 굽는다.
  자리를 1픽셀 단위로 잡을 수 있고 색·글자 크기를 문서와 맞출 수 있다.
- mermaid 는 쓰지 않는다. 글꼴과 색을 문서에 못 맞춘다.
- 색은 본문과 같은 것만 쓴다. 남색 `#243B5E`(주인공) · 흐린 남색 `#2C4A78` · 연파랑 `#DCE4F0`(바탕) ·
  주황 `#E8873A`(두 번째 축·강조) · 연주황 `#F6DCC4`(갈래 구분) · 빨강 `#C0392B`(경고·목표) ·
  회색 `#8A94A6`(눈금·각주).
- 인쇄에서 폭이 줄어든다. **글자 14~15px, 선 2.4~2.6px** 로 잡는다.

## 3. 사업계획서 구성요소 (P-S-S-T)

| 항목 | 쓸 것 |
|---|---|
| **문제인식 (Problem)** | 고객이 겪는 진짜 문제를 정의. 상단에 캐치프레이즈를 두어 핵심을 직관적으로 전달 |
| **실현가능성 (Solution)** | 제품·서비스 개발 계획을 구체적으로. **5월~내년 1월의 최종 산출물과 수익 창출 구조를 연결** |
| **성장전략 (Scale-up)** | 정부 지원금 의존이 아님을 보인다. 투자 유치·사업 확장 계획을 포함해 지원 필요성을 높인다 |
| **팀구성 (Team)** | 인력의 전문성과 역할 분담을 상세히. 실행력을 증명하는 자리 |

## 4. 모두의창업 편집기 제약

- 되는 것: 굵게 · 기울임 · 취소선 · H1 · H2 · H3 · 글머리 기호 · 번호 매기기 · 인용 · `--`(짝대기).
- **표·차트는 전부 이미지.** HTML·마크다운 표를 붙일 수 없다.
- **이미지는 전 문항 통틀어 10장.** 문항마다 몇 장 썼는지 세어 보고한다.
- 나머지는 전부 문장.

## 5. 만드는 법

작업 폴더에 이렇게 둔다.

    본문.html          PDF 원본. 여기를 고치고 다시 굽는다
    _doc.css           PDF 스타일(A4·20mm 여백·표·불릿·인용)
    _style.css         PNG 스타일
    _tables.html       표들의 정본. <!--T1-->…<!--/T1--> 로 나눈다
    _chart*.svg        그림들의 정본
    img*.html          표·그림 하나를 PNG 로 굽는 껍데기
    Q2-이미지*.png     모두의창업에 붙일 이미지
    Q1-Q2.md           붙여넣기용 텍스트(PDF 와 같은 내용)

**표를 고칠 때는 `_tables.html` 을 고치고 `본문.html` 에 반영한다.** 두 곳이 어긋나면 안 된다.

### PDF 굽기

    CH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
    "$CH" --headless --disable-gpu --no-pdf-header-footer \
      --print-to-pdf="빌탐정_사업계획서_Q1-Q2.pdf" "file://$PWD/본문.html"

### PNG 굽기 (높이를 재고 그만큼만 찍는다)

    cp img1.html _m.html
    echo '<script>document.title="H"+Math.ceil(document.documentElement.scrollHeight)+"E";</script>' >> _m.html
    H=$("$CH" --headless --disable-gpu --window-size=1000,300 --dump-dom "file://$PWD/_m.html" \
        | grep -o 'H[0-9]*E' | head -1 | tr -d 'HE')
    "$CH" --headless --disable-gpu --hide-scrollbars --force-device-scale-factor=2 \
      --window-size=1000,$((H+8)) --default-background-color=ffffff \
      --screenshot="Q2-이미지1.png" "file://$PWD/img1.html"
    rm -f _m.html

**크롬이 안 끝나고 매달리면** 남은 헤드리스 프로세스를 죽이고 다시 한다.
`pkill -9 -f "Google Chrome Helper"` · `pkill -9 -f "Google Chrome.*--headless"`.
`--user-data-dir` 을 주면 오히려 더 잘 매달린다. 주지 않는다.

## 6. 수치를 구할 때

- **우리 DB 가 먼저다.** 서울 거래 추세·건물 수·업체 수는 `master` 에서 직접 뽑는다.
  `PGPASSWORD=test psql -h localhost -p 55432 -U postgres -d billtamjung`.
  뽑았으면 자료 줄에 「빌탐정 보유 국토교통부 실거래가 자료」처럼 무엇을 어떻게 걸렀는지 적는다.
- 추정 정확도는 백테스트 메모가 정본이다(적정가 16.99% · 임대 28.8%).
  「오차를 몇 % 줄였다」가 아니라 **무엇과 대조했고 얼마가 나왔고 어떻게 줄일지**를 쓴다.
- WebSearch 가 자주 죽는다. 죽으면 WebFetch 로 원문 페이지를 직접 연다.
- 비상장·비외감 법인의 매출액은 공시되지 않는다. 억지로 추정하지 않는다.

## 7. 내보내기 전 확인

- [ ] `~다.` 로 끝난 문장이 남아 있지 않다 (대표 인용문 제외)
- [ ] 대시(—)가 본문에 없다
- [ ] 표마다 번호·이름·자료 줄이 있다
- [ ] 표의 값을 본문이 되읊지 않는다
- [ ] 칸 안에서 낱말이 두 동강 나지 않는다
